# 家庭菜单 · 本地点餐服务

一个跑在自己电脑上的家庭菜单 + 点餐 + 库存 + 本周计划服务。把常做的菜录进去
（分类、做法、调料用量、图片、步骤、备注），家里人用手机连同一个 WiFi 打开网页就能点餐，
做饭的人看到点餐单和自动汇总的买菜清单；周末还能把想做的菜排进「本周计划」，照着汇总单一次买齐。

**一份菜谱，所有家庭共享；点餐、库存、本周计划，每个家庭各记各的。**
家里人也可以给自己家记**私菜**，公共菜谱由管理员维护（见第九节）。
家庭可以用房号（301）、门牌（西苑 2 栋 501）或者随便起的称呼来命名。

**零第三方依赖**，不需要数据库、不需要 `npm install`，有 Node.js 就能跑。

想让它更省事，可以接上你自己的 MiniMax 账号：**拍张照自动写菜谱**、
**把抄来的菜谱文字粘进去自动拆**、**把乱菜谱整理规范**、**厨房助手排一整晚的备餐时间轴**
（见第十节，不配也完全不影响使用）。AI 只帮你把菜谱填成表单，**不碰你的菜单**。

## 一、启动

### 方式 A：双击（Windows）

双击 `start.bat`。命令行窗口会显示访问地址：

```
  本机访问：   http://localhost:8787
  手机访问：   http://192.168.x.x:8787   ← 家人连同一个 WiFi 打开这个
```

**这个窗口要一直开着**，关掉服务就停了。

### 方式 B：命令行

```bash
node server.js
# 或者
npm start
```

换端口：`set PORT=8888 && node server.js`

### 前置条件

装了 [Node.js](https://nodejs.org/zh-cn)（LTS 版本即可，16 以上都行）。
检查：`node -v`

## 二、家里人怎么用

1. 手机连上和电脑**同一个 WiFi**
2. 浏览器打开启动窗口里显示的「手机访问」地址
3. 首页是菜单，点开任意一道菜看做法和调料
4. 点右下角 **「今天想吃这个」** → 选自己的头像、填人数、备注 → 提交
5. 做饭的人打开「点餐」页，能看到待做清单和**自动汇总的买菜清单**（可以勾掉已买的，也可以一键复制发到家庭群）
6. 管理员负责点 **「🔥 一键开做」** 或逐道更新「开做 / 完成」；普通用户可以看到状态，但不能修改做饭状态

周末想提前备菜，打开「🗓️ 计划」页把这周要做的菜排上，**一次买齐**里就是照着买的清单。

想让家人免登录收藏：手机浏览器「添加到主屏幕」，图标和 App 一样。

### 一键开做

点餐页顶部有 **「🔥 一键开做 N」**（N = 当前待做数量），和「👨‍🍳 厨房助手」并排。

- 有待做菜时才出现，点一下**所有待做的一起转成制作中**，不用一道道点
- 转完之后页面自动切到「制作中」，接着逐道点「完成」就行
- 下过厨的应该不用一道道点「开做」，这个按钮就是为这个场景省事的
- 删菜、记菜、管理入口都还在原处，没被挪走

## 三、多个家庭

### 加一个家庭

点顶栏右上角的 **「🏠 名字 ⌄」** 按钮 → 「＋ 添加家庭」。名字可以是：

- 房号：`301`、`502`
- 门牌：`西苑 2 栋 501`
- 称呼：`外婆家`、`单身公寓`

还能挑个图标、填一句备注（住哪、几口人）。

### 怎么分的

| 内容 | 是否共享 |
| --- | --- |
| 菜品、分类、做法、图片 | **全体共享**，录一次所有家庭都能用 |
| 点餐单 / 买菜清单 / 买菜记录 | **按家庭分开** |
| 库存（食材、数量、保质期） | **按家庭分开** |
| 本周计划 | **按家庭分开**，各家这周各自安排 |
| 家庭成员、头像 | **按家庭分开**，各管各的 |

### 切换家庭

顶栏那个按钮就是切换器，弹层里能看到每个家庭当前的「几位家人 · 几道待做 · 几样库存 · 几样要处理」，
点一下就切过去。

**每台设备记住自己选的是哪个家庭**（存在浏览器本地），
所以 A 家手机上固定在 `301`、B 家手机上固定在 `502`，互不干扰；同一台电脑开两个浏览器也可以各选各的。

### 管理家庭

管理页 →「家庭」区块：重命名、换图标、删除。
删除一个家庭会连它名下的点餐、库存和本周计划一起清掉（会先弹窗告诉你各有多少条）。

> 至少会保留一个家庭，删不掉最后一个。

## 四、库存（家里有什么食材）

底部第五个页签「🧊 库存」，**每个家庭一本独立的账**。

### 能记什么

食材名、分类、数量 + 单位、保质期到哪天、备注。
分类覆盖了家里会囤的东西：

> 肉类 · 蛋类 · 奶制品 · 蔬菜 · 水果 · 主食粮油 · 豆制品 · 水产海鲜 · 冷冻食品 · 饮料 · 调味干货 · 零食 · 其他

### 录入

点右下角「＋ 记一样食材」：

- **常见食材快选** —— 内置 148 种常见食材（猪里脊、鸡蛋、纯牛奶、黄瓜、可乐、蚝油……），
  按分类列出，点一下自动填好名字、分类、单位，还有**参考保质期**（鸡蛋 20 天、可乐 180 天、青菜 3 天…）
- 也可以直接搜索，或者自己输入表里没有的
- 保质期除了日期框，还有「明天 / 3 天 / 一周 / 一个月」快捷按钮

### 看和改

- 按分类分组，分类顺序固定（肉→蛋→奶→菜…），同分类里快过期的排最前
- 数量直接用 `−` `＋` 调；称重的按大份走（g 一次 50、kg/斤 一次 0.5），论个的一次 1
- 保质期徽标四档：**已过期**（红）→ **今天到期**（橙）→ **3 天内**（橙）→ **还剩 N 天**（绿）→ **未填保质期**（灰）
- 顶部有临期/过期汇总卡片和红色提醒条，一键「看看」筛选、一键「清理」批量删掉
- 底部页签上的红色角标 = 这个家庭有几样该处理了

### 批量操作

上面那个「清理」只管临期的那批。日常整理想一次动好几样，用 **「☑ 批量操作」**：

1. 点库存页顶部的 **「☑ 批量操作」** 进入多选（右下角的「＋ 记一样食材」会先让位，避免误触）
2. 每行前面变成勾选框，勾上要动的；顶栏浮出工具条：**「☐ 全选 / 已选 3 / 12 / 📅 改保质期 / 🏷 改分类 / 🗑 删除 / 退出」**
3. 「全选」选中的是**当前能看到的**那些（筛了「临期」就只全选临期的），「已选 N / M」里的 M 也跟着变，不会出现「全选了 10 样却删掉 12 样」
4. 工具条上的按钮在没勾东西时是灰的 —— 不勾不动手

三个批量动作：

| 按钮 | 做什么 |
|---|---|
| **📅 改保质期** | 快捷选 +3 天 / +1 周 / +2 周 / +1 个月 / +3 个月（都相对今天算），也能直接指定一个日期，或者「清空保质期」 |
| **🏷 改分类** | 13 个预设分类点一下就换，也能新开一个分类 |
| **🗑 删除** | 弹窗确认，**写清楚要删哪几样**（只念前三个名字），确认后一次删完 |

批量删除是**不可撤销**的（想找回只能去管理页恢复备份）。别拿它清空整个库存用——真要清空就一条条划，偶尔手滑一次代价太大。

> 改保质期和改分类是批量**更新**不是删除，点错了改回来就行，没那么危险。

### 和买菜清单联动

点餐页的买菜清单里：

- **家里已有的会标出来** —— `🏠 家里有 4个`，不用买
- **家里没有的给个「入库」按钮** —— 买回来点一下，数量和单位会从菜谱用量自动解析（比如「1 小勺」直接记成 1 小勺），记进当前家庭的库存
- **买完一袋记一袋** —— 勾上买回来的那几样，冒出的工具条里有「🧊 全部入库」，一次全记进去，入完库自动把勾清掉

> 不会自动扣减库存：菜谱写的是「2 个」，库存记的是「400g」，两个单位对不上，
> 自动算只会算错。所以改成「显示家里有多少 + 人工点入库」。

## 四·五、批量操作（能勾的地方都能勾）

除了库存，下面这几处也都支持多选。规律是一样的：

> 点「**☑ 批量操作**」进入多选 → 勾上要动的 → 顶栏工具条上挑动作 → 完事点「退出」。

| 位置 | 入口 | 能批量做什么 |
|---|---|---|
| **菜品管理**（管理页） | 「☑ 批量操作」 | 🏷 改分类 · 🏷 标签（加/去标签、标拿手菜）· 🗑 删除 |
| **点餐单** | 「☑ 批量操作」（管理员） | 🔥 开做 / ✓ 完成 · 🗑 删除 —— 普通用户只读状态 |
| **本周计划** | 「☑ 批量操作」 | ✕ 拿掉 |
| **库存** | 「☑ 批量操作」 | 📅 改保质期 · 🏷 改分类 · 🗑 删除 |
| **买菜清单** | 直接勾每行那个 ✓ | ☐ 全勾 · 🧊 全部入库 · 复制勾中的 |
| **「我要点餐」弹层** | 勾菜名 | 一次下好几道，按钮变成「提交点餐（N 道）」 |
| **「加一道菜」弹层** | 勾菜名 | 一次排好几道，按钮变成「加 N 道进去」 |

### 三个约定

**全选只针对「你眼前这一批」。** 筛了「临期」再全选，选中的是临期的那些，「已选 N / M」里的 M 也跟着变。
不会出现「显示全选了 10 样，删掉却是 12 样」。

**批量删除必须真的勾了东西。** 没勾的时候工具条是灰的、点不动；服务端也再挡一道 ——
`DELETE /api/orders` 不带 `ids` 直接报 400，绝不会「没传参数就当成全选」。

**买菜清单不另起「多选模式」。** 每行那个 ✓ 本来就是「已经买了」，它同时就是勾选：
勾上就冒出工具条。多造一个「选中了但还没买」的概念，反而更容易点错。

### 两个「勾选式」弹层

「我要点餐」和「加一道菜」都是**先勾上、最后一起提交**，不是点一下就立刻生效：

- 只勾一道时，「我要点餐」的菜名框仍然显示那道菜名，和以前一模一样
- 勾 ≥2 道时，按钮才变成「提交点餐（N 道）」/「加 N 道进去」
- 提交后一次完成，中间不会插入半截状态

## 四·六、留言板与菜品互动（一家人在这儿说话）

底部第四个页签 **「💬 留言」**（菜单 → 计划 → 点餐 → **留言** → 库存 → 管理）。
菜单页每张菜卡片的底下也有一排互动按钮。

### 留言板

写一条只要三步：**点一下自己是谁** →（可选）**挑个贴纸** → **写完点「发一条」**。

- 「我是谁」那一排是这个家庭登记过的成员，点头像就切换；没登记过也能直接写名字
- 贴纸 🍳🛒🌶️🍚🎉⚠️💤🧊 是选填的 —— 一屏扫过去，是谁的事、大概什么性质，不用读字
- 留言按**家庭分开**，和点餐、库存一个规矩：切到哪个家庭就只看哪个家庭的话

### 三种互动

| | 怎么用 | 规矩 |
|---|---|---|
| **表情** | 点已有的 👍1 再点一下取消；点「＋」挑一个新的 | 同一个人对同一个表情只能出现一次；一条留言最多 6 种不同表情 |
| **🙋 我来** | 认领 ——「今晚我做饭」「我去买菜」 | **一条留言只能有一个人认领**。别人来点会提示「XX 已经认领了」，不会默默顶掉人；本人再点一次是取消 |
| **💬 回复** | 一条留言底下能接一串话 | 回复跟着留言走，删留言时一起没 |

### 菜品互动区

菜单页每张菜卡片底下那排：

- **🍽 想吃** —— 点一下表示想吃，按钮会变橙并显示人数；长按（悬停）能看到是谁点的
- **👩‍🍳 我来做** —— 认领下厨。**一道菜只认一个人**，别人点会被挡掉并提示是谁认领了；本人再点是取消
- **💬** —— 打开这道菜的专属留言。留过言就会显示条数

卡片整体是「点开看做法」，所以这排按钮点下去**不会**顺手把菜谱也打开。

### 几条约定

**删掉一道菜不会抹掉别人的话。** 挂在它下面的留言会退回留言板继续留着，
只有那笔投票会跟着清掉 —— 没人认领的票留着没意义，别人写的话不该因为删个菜就没了。

**删家庭会带走它的留言。** 和点餐、库存、计划一样。

**批量删留言**：留言板点「☑ 批量操作」，勾上几条一次删完。
没勾的时候删除按钮是灰的；服务端也再挡一道 —— `DELETE /api/notes` 不带 `ids` 直接报 400。

**页签上的数字是「今天」说了几句**，不是总数。

**留言不需要管理口令。** 写留言、回一句、点个想吃，都是家里人随手做的事，
和点餐 / 库存 / 计划一个待遇。口令还会挡住共享菜单、做饭状态、家庭管理、系统设置和备份。

### 数据在哪

新开一个文件 `data/notes.json`，里面装两块：

```jsonc
{
  "notes": [ /* 留言板留言 + 菜品留言，正文/表情/认领/回复都在里面 */ ],
  "votes": { "d_某道菜": { "want": ["我"], "cook": ["妈"] } }
}
```

删菜、删家庭、换分类的级联都在服务端处理；备份 zip 里也带着它，恢复回来是原样。

## 五、本周计划（一次买齐）

底部第二个页签「🗓️ 计划」。**先想好这周做哪几道菜，再照着单子一次把菜买齐。**

菜单页顶部也有一张「🗓️ 本周计划」入口卡片，两个地方都能进。

### 怎么把菜排进来

三条路都行：

| 入口 | 怎么用 |
| --- | --- |
| 菜品详情页 | 点开任意一道菜 →「＋ 加入计划」，加完按钮变「✓ 已在计划里」 |
| 计划页右下角 | 「＋ 加一道菜」→ 从菜谱里挑，或者自己写一道菜单里没有的 |
| 菜单页顶部 | 「🗓️ 本周计划」卡片直接进计划页 |

份量会自动从菜谱带过来（「2 人份」「3 碗」），不用重填。

> 同一道菜一周内只排一次，重复加会被拦下并提示。菜谱删了也不影响已经排好的计划——
> 计划里存的是菜名快照。

### 一次买齐

计划页下半部分是**照着单子采购**的汇总：

```
一次买齐
15 样待买 · 15 样家里没有          [复制清单]

✓ 番茄     番茄炒蛋 2 个                    [入库]
✓ 白糖     番茄炒蛋 1 小勺 · 宫保鸡丁 1.5 勺  [入库]
✓ 鸡腿肉   宫保鸡丁 400g                    [入库]
✓ 生抽     宫保鸡丁 2 勺 · 拍黄瓜 1 勺        [入库]
...
```

- **多道菜用到的同一味料会合并成一行**，后面写清分别是哪几道菜要用
- **家里已有的会标出来**，和买菜清单一个逻辑
- **「入库」按钮**：买回来点一下，数量单位从菜谱用量自动解析，直接记进当前家庭的库存
- **「复制清单」**：整张单子复制走，发家庭群或者抄在纸上

> 只统计**菜谱里有的**菜。自己随手写的一道菜没有调料用量，混进来只会显示一堆没意义的空行。

### 翻周

计划页顶上有一条 `‹ 10月12日 - 10月18日 ›`，左右箭头翻上一周/下一周，
中间显示「本周」「下周」或者具体日期。

**一周从周一开始算**。周三加的菜会自动归到本周一那一栏。

空的一周显示「这一周还没安排」，可以直接开排。
「清空这一周」只清当前这一周，不会动别的周。

### 和点餐的区别

| | 本周计划 | 点餐 |
| --- | --- | --- |
| 什么时候用 | 周末看「这周吃什么」，提前买菜 | 今天谁要吃 |
| 按什么分 | 按**周** | 按**人** |
| 采购清单 | 按整个计划的菜汇总 | 按点餐（可以只筛某个人）汇总 |

两个页签各自独立，最后都能出买菜清单。

## 六、家庭成员 / 按人分餐

### 登记成员

管理页 →「家庭成员」→ ＋添加。注意这里是**当前选中的那个家庭**的成员，
想改别的家庭，先切过去再改。

一个家庭可以有多个「家庭管理员」。编辑成员时把权限设成「管理员」即可；每个管理员都有自己的登录 ID 和密码，不能把最后一名管理员降级或删除。登录 ID 可以写汉字、字母或数字，例如「厨房大管家」「mom01」；密码可以是汉字、字母、数字和符号，不要求只能输入数字。

### 点餐单按家人分组

点餐页默认就是**按家人分组**的，每组头部直接写清这人要吃几道、共几份：

```
👨 爸爸        1 道 · 共 3 份
   宫保鸡丁

👩 妈妈        2 道 · 共 4 份
   拍黄瓜、番茄炒蛋
```

分餐、分装饭盒照着分就行。想看时间顺序，点右上角「⇅ 改成按时间」切回去。

### 只看某一个人

点餐页有一排成员头像胶囊，点一下就只看 TA 的点餐——**买菜清单也跟着过滤**，
只看妈妈时就只列妈妈那几道菜要用的料。

### 成员统计

管理页每个成员后面显示「点过 N 次 · 共 M 份」，看看谁最捧场。

> 删除成员不会删掉 TA 走过的点餐记录，只是分组显示时不再有专属头像。

## 七、菜谱能记什么

| 字段 | 说明 |
| --- | --- |
| 菜名 / 分类 | 分类可自由增删改名，比如「家常菜」「主食」「凉菜」 |
| 一句话介绍 | 卡片上显示，家人一眼认出 |
| 图片 | 多张，第一张做封面；上传时自动压缩到 1400px，不用担心占空间 |
| 份量 / 耗时 / 难度 | 「2-3 人份」「30 分钟」「简单」 |
| 标签 | 下饭、快手、宴客……搜索也能搜到 |
| **通用调料** | 名称 + 用量，**每种做法都要用**的那些，会汇总进买菜清单 |
| **做法步骤** | 一行一步，支持一菜多做法（家常版 / 快手版），**每个做法能带自己独有的调料**（见下） |
| **备注** | 经验、禁忌、替换方案（比如「花生最后放，久炒会软」） |
| 拿手菜标记 | 显示星标 |

### 一道菜多种做法，各自带各自的调料

一道菜红烧、清蒸、微辣往往差着几味料。与其把调料全堆在菜品上、然后分不清哪个做法要哪些，
不如分两层记：

| 记在哪 | 什么时候用 |
| --- | --- |
| 菜品的**通用调料** | 每种做法都要用的。糖、盐、酱油、主料这些 |
| 每个**做法里的调料** | 只有这个做法额外要的。微辣版多一勺小米椒，清蒸版多一把葱姜 |

编辑菜谱时，每个做法卡片里有一块 **「这个做法独有的调料 —— 上面的通用调料它也能用，这里只写它额外要的」**，
点「＋ 加一味」往下加即可；点调料行右边的 ✕ 删掉。

菜品详情页里，通用调料单独立一块，下面每个做法底下再单独列出它自己那几味。

买菜清单会**把通用调料和各做法的调料一起汇总**，并写清来自哪道菜的哪个做法：

```
蒜        拍黄瓜（快手版） 3 瓣 · 孜然牛肉（微辣版） 4 瓣
小米辣    孜然牛肉（微辣版） 1 勺
```

> **老菜谱不用动。** 以前记的做法没有这一层字段，打开时自动补成空，你原来记的用量和步骤一样都不会少。
> 以前记在菜品上的调料，继续当「通用调料」用就行。

```
data/
  dishes.json       菜品
  categories.json   分类
  households.json   家庭（含各家的成员）
  users.json        全局账户资料和密码摘要（不保存账户令牌）

  settings.json     店名、欢迎语、管理口令
uploads/            图片文件
```

纯文本 JSON，随时可以自己看、可以手动改。

**换电脑 / 重装系统前**：管理页 →「⬇ 导出备份」，会下载一个 `menu-backup-YYYY-MM-DD.zip`
（里面是 `backup.json` + `uploads/` 全部照片）。新机器上「⬆ 恢复备份」把这个 zip 选进去就行，
菜谱和照片一起回来。

> 想加一道新菜前，先导出一份，养成习惯。

### 从老版本升级

第一次跑新版本时会自动迁移，不用手动改任何东西：

- 没有 `households.json` → 自动建一个默认家庭「我家」
- 老版本 `settings.json` 里的家庭成员 → 搬进第一个家庭
- 没有 `householdId` 的历史点餐 → 归到第一个家庭
- 没有 `plans.json` → 自动建空文件
- 没有 `notes.json` → 自动建空留言板，老数据一条留言都不会少（本来也没有）
- 旧家庭成员自动建立全局账户并补上 `userId`，旧密码迁移为摘要；没有旧密码的账户初始密码为 `123456`
- 重复 id、坏 JSON → 自动去重 / 备份成 `.corrupt-时间戳`，不丢原始文件

### 数据存在哪、断了怎么办

```
data/       菜谱、分类、家庭、点餐、库存、计划、留言（纯文本 JSON）
uploads/    菜品照片
backups/    自动快照（服务自己写的，别手动改）
```

写入是**原子的**：先写 `.tmp` 再改名覆盖，断电不会留下半截 JSON。
正常关停（Ctrl+C、systemd stop）会把内存里的改动全量刷盘。
最坏情况是 `kill -9` 或拔电，**只丢最后 0.15 秒内的改动**。

**别让新旧两台机器同时跑同一个 `data/` 目录** —— 两边都会全量覆盖，会打架。

## 八·五、备份（数据出事时的后悔药）

### 自动快照

服务**每次启动**、以及**每天凌晨 3 点**自动打一份快照到 `backups/`，保留最近 7 份。

管理页 →「数据」区里就一行，不用去数：

```
⬇ 导出备份            ⬆ 恢复备份

🗂️ 自动备份                          💾  ↩
   已自动存 5 份，保留最近 7 份，在 backups/ 目录
```

- **⬆ 恢复备份** —— 就是**选一个备份文件**（导出时下的那个 zip），整个库回到那一刻的状态。
  这是恢复数据的主路径，选文件就行，不用在一列快照里翻
- **💾** —— 改重要东西之前先点一下，立刻手动存一份（比等凌晨三点靠谱）
- **↩** —— 「回到最近一次自动备份」，一键回退。会弹窗说清楚**这之后的改动会没**，确认了才动

手动存的和自动存的放在同一个 `backups/` 目录里，一共留 7 份，旧的自动清掉。

> 快照里含有管理口令明文，所以这些入口都需要口令，没解锁看不到、也点不动。

### 导出备份（换电脑用）

管理页 → 「⬇ 导出备份」，下下来的是一个 **zip**，里面有：

```
backup.json      菜谱、分类、家庭、成员、点餐、库存、计划、设置
uploads/         全部菜品照片
```

新机器上装好、起一次服务，然后管理页 → 「⬆ 恢复备份」选这个 zip 就行。
**老版本导出的纯 JSON 备份也照样能恢复**，不会因为你升级了就打不开。

### ⚠️ 并发限制，先看一眼

这个服务是**单进程 + 整份文件覆盖**，没有版本校验：

| 场景 | 安全性 |
| --- | --- |
| 多人同时**点餐、查库存、看菜单、各自记东西** | ✅ 安全 |
| 两人同时**编辑同一道菜的菜谱** | ❌ 后保存的人会覆盖前一个人的修改 |

日常一家几口人同时用完全没问题。要真正支持「多人同时改同一道菜」，
需要给保存加上版本比对（发现对不上就提示「已被别人改过」），
这个还没做。

### 公网部署要额外做的

默认 `HOST=0.0.0.0`，也就是监听所有网卡。放内网没问题，
但放到有公网 IP 的服务器上时，**务必**：

1. 在管理页设一个 `adminPin`（不然谁都能改你的菜谱）
2. 用 `set HOST=127.0.0.1` 让它只监听本机，前面挂 Nginx 反代并配 HTTPS
3. 用 systemd 托管，别裸跑 `node server.js`（SSH 一断进程就没了）

## 八·七、内存占用（2G 小机器怎么活下来的）

照片是这个服务里唯一的大块内存。孜然牛肉那一张成品照就有几百 KB，
攒到几百道菜、上百张照片，打一次备份就够把一台 2 核 2G 的机器顶到 OOM。

### 改了什么

**打包改成流式。** 以前是把每张照片读成 Buffer、连同压缩结果一起攒在一个数组里，
最后一次性拼出整个 zip —— 峰值内存约等于「照片总量 + 压缩总量」。
现在每条写完就释放（`zipWriteTo(entries, write)`），照片在 `read()` 被调用的那一刻才进内存，
写完立刻出栈。

**导出先落临时文件再发。** 以前边打包边往 socket `res.write`，
客户端一慢，socket 缓冲区就把压缩结果又攒回内存里 —— 换个地方 OOM 而已。
现在先写到 `os.tmpdir()`，再用 `createReadStream().pipe(res)` 发出去。

**导入上限从 128MB 降到 64MB。** 恢复备份要把整个 zip 读进内存，
加上解析出来的 JSON 对象，峰值大约是文件大小的两到三倍 —— 64MB 的 zip 峰值就到 256MB。
嫌小可以调：`set MEM_IMPORT_MB=128`。

**启动时限制堆上限。** `start.bat` 和 `npm start` 都带 `--max-old-space-size=384`。
这是第二道防线：让 V8 早点抛 OOM 并被我们接住，比拖垮整台机器强。

### 实测（120MB 照片，端到端）

| | 改之前 | 改之后 |
| --- | --- | --- |
| 打备份峰值 RSS | 305 MB | **73 MB** |
| 导出峰值 RSS | 181 MB | **74 MB** |
| 打备份耗时 | 2216 ms | 2254 ms |
| 导出耗时 | 21253 ms | 19421 ms |
| 产出的 zip 字节数 | 122889 KB | 122889 KB（一致） |

**耗时没变，产物一字不差，只有内存降下来了** —— 这是纯收益，没有折衷。

> 量内存要看 RSS 不能看 `heapUsed`：照片是 Buffer，压根不在 JS 堆里，
> 只盯 `heapUsed` 会得出「备份不吃内存」的错误结论。

### 启动时它会告诉你

```
  内存  堆上限 384MB · 现在用 52MB（物理 2048MB）
```

机器物理内存 ≤ 3G、而堆上限又超过物理内存 75% 的时候，会额外响亮地提醒你调参数。
堆上限想改就改启动命令里的 `--max-old-space-size`。

### 想自己量一遍

```bash
node --expose-gc _memtest.js          # 只比 zip 打包函数：全内存 vs 流式
node _memrun.js 60 2 --old            # 端到端，旧写法
node _memrun.js 60 2                  # 端到端，新写法（参数：照片数、每张 MB）
```

`_memrun.js` 会在临时目录起一个独立实例、造照片、走真接口，
**不会碰你的 `data/`**。它里面内联的 zip 实现是 `server.js` 的副本 ——
改了 `server.js` 的打包代码，记得同步一下。

## 九、账户、家庭和管理口令

新设备打开后先进入登录/注册页。注册时可以留空登录 ID，系统会生成一个可修改的全局 ID（例如 `用户-AB12`）；
初始密码是 `123456`，可以继续使用，但设置页会持续提示风险。登录后身份跨家庭保留，当前账号最多加入 5 个有效家庭。

从设置页可以创建家庭或申请加入其他家庭。创建家庭不需要超级管理员批准，创建者立即成为这个家庭的管理员；
申请只有在目标家庭管理员批准后才建立成员关系，申请人可以同时申请普通成员或家庭管理员，最终身份由目标家庭管理员选择；待处理申请不占 5 户名额。一个家庭可以有多个管理员，不能删除或降级最后一名管理员。

底部导航固定为：**菜单、计划、点餐、留言、库存、设置**。菜单是第一栏，设置是最后一栏；共享菜和「我家私房」在菜单页内切换，
普通成员只能维护自己添加的私菜，家庭管理员可以管理本家庭菜单、成员和做饭状态。设置页的管理内容按「家庭与成员 / 菜单与日常数据 / 系统与备份」折叠，顶部搜索框支持模糊搜索管理项。

家庭管理员可以在「家庭与成员」里编辑家庭名称、图标和备注，也可以把成员设为管理员或处理加入申请。顶栏的「🎲 随机来一道」支持先选共享/私菜范围、分类、标签，以及「今天没做过」「排除已点餐」条件。

全局管理口令仍在设置页配置。输入正确后，服务端把超级管理员授权绑定到当前账户和设备，固定有效 12 小时；
到期后恢复原来的家庭角色，需要重新输入口令。超级管理员可以管理所有家庭、共享菜单、做饭状态、备份、系统设置和 AI。
修改或清除全局口令会立即撤销已经发出的超级授权。没有设置全局口令时保留旧版开放模式，但账户仍按家庭关系显示工作区。

### 三层身份和登录方式

- **超级管理员**：当前账户输入全局管理口令后获得 12 小时授权，能管理所有家庭、共享菜单、做饭状态、备份、系统设置和 AI。
- **家庭管理员**：一个家庭可以有多个；在自己管理的家庭内维护共享菜单、私菜、成员、申请和做饭状态，不能越权管理其他家庭。
- **普通成员**：可以点餐、维护库存/计划/留言，以及修改自己添加的私菜；不能修改共享菜单、别人的私菜或做饭状态。

内部成员 ID 是系统生成的稳定值，用户不需要填写。全局登录 ID 全平台唯一，支持汉字、字母和数字；密码支持一般文本，不再使用「只能填数字 PIN」的限制。旧版本成员会自动迁移到账户身份。

### 共享的和私有的，界线在哪

这是这套权限模型的全部：**共享的归管理员，本家的归本家。**

| | 共享（🌏） | 本家私菜（🔒） |
| --- | --- | --- |
| 谁看得见 | 所有家庭 | 只有本家 |
| 谁能改 | 作者本人或超级管理员；新共享菜由家庭管理员发布 | 作者本人或超级管理员 |
| 怎么来的 | 管理员建的、或者私房菜「＋ 添加到共享」复制来的 | 家里人自己加的，或者从共享菜「👇 收进我家」复制来的 |

菜谱编辑器只编辑菜谱内容，不切换共享/私房归属。新菜跟随当前菜单栏目创建；已有菜保留原范围。要跨到另一边，使用下面的复制操作。

### 👇 收进我家

共享菜谱是大家的，家里人想按自家口味改怎么办？**在共享菜上点「👇 收进我家」**：

- 复制一份到你家，菜名原样，调料、做法、图片全都带过来
- **公共那份一个字都不会动** —— 别家看到的还是管理员维护的那版
- 从此这份是你的私菜，随便改随便删

### 🌏 添加到共享

家庭管理员可以从本家私房菜详情点「＋ 添加到共享」，把自家做法发布成共享菜：

- 共享菜单得到一份独立副本，原私房菜继续留在本家
- 之后修改或删除其中一份，不会影响另一份
- 家庭私有分类会映射到共享可见分类；家庭原料 ID 不跨范围复用，菜谱中仍保留原料名称和用量
- 同一道源菜在同一目标范围只添加一次

共享和私房之间的转换都通过菜谱详情里的添加操作完成，不需要编辑时切换“谁看得见”。普通成员可以把共享菜收进本家；发布到共享需要管理员权限。

### 🙋 申请加入家庭

别人想进你家：切到那个还没加入的家庭 → 点「申请加入」→ 填名字、申请身份（和一句你想说的话）。

- **提交不需要口令** —— 人总得有个申请入口
- **批准 / 拒绝要口令**，那是管理员的活
- 申请管理员身份不会自动生效，管理员可以选择批准为普通成员或家庭管理员
- **批准 = 真的把人加进这个家庭的成员列表**，不是只改个「已通过」的标记却让人家成员列表里找不到自己
- 同一个人申请同一家只留最新一条，不会刷出一长串等价的待办
- 申请人自己能看到自己那条的状态（待处理 / 已通过 / 已拒绝）

### 它是真的锁，不是装样子的

口令**只存在服务端**，前端永远拿不到明文；解锁时服务端发一枚会话 token（12 小时自动过期），
之后改菜谱、改家庭、导出备份都要带这枚 token。没带就一律 401。

具体挡住这些：

| 操作 | 没口令时 | 设了口令后 |
| --- | --- | --- |
| 改共享菜谱 / 共享分类 / 家庭 | 随便改 | **要口令** |
| 新增或修改本家私有菜谱 / 分类 | 随便改 | **普通成员只改自己的；家庭管理员可改本家全部** |
| 开做 / 完成 / 删除点餐记录 | 随便改 | **要口令** |
| 导入备份 | 随便导 | **要口令** |
| 导出备份（含口令明文） | 随便导 | **要口令** |
| 上传图片 | 随便传 | **要口令** |
| 提交点餐、记库存、排本周计划、留言 | 随便用 | **照样随便用** ← 家人的日常功能不被挡 |

所以局域网里别人拿手机扫你电脑的地址，可以做日常点餐和维护自家内容，但改不了共享菜单、做饭状态和管理员设置。要成为某个家庭的管理员，必须先用这个家庭里已登记的管理员身份登录。

### 改口令 / 取消口令

- **换口令**：设置页填新值保存即可，旧会话立刻全部失效
- **取消口令**：设置页勾上「取消口令保护」再保存
- **忘了口令**：改 `data/settings.json`，把 `adminPin` 改成 `""` 再重启服务

口令只加锁管理区，**不影响已保存的数据**，随时能关。

## 十、AI 厨房助手（可选，接你自己的 MiniMax）

三个能力，都跑在你自己的 MiniMax 账号上，不经过任何第三方：

| 入口 | 在哪 | 干什么 |
| --- | --- | --- |
| 📷 拍张照，AI 帮我写这道菜 | 新增 / 编辑菜品 | 拍一张成品照，自动填菜名、分类、通用调料、步骤 |
| 📋 粘贴文字，AI 帮我写 | 新增 / 编辑菜品 | 从别处抄来的菜谱文字（公众号、外卖页、老妈发来的），粘进去拆成结构化的调料和步骤 |
| 🧹 让 AI 把这份菜谱整理规范 | 新增 / 编辑菜品 | 把随手记的乱菜谱理顺：「够两个人吃的」→「2 人份」 |
| 👨‍🍳 厨房助手 | 点餐页（待做 ≥ 2 道时出现） | 把今晚几道菜排成一条**备餐时间轴**：从「开始洗菜」到最后一道上桌，每步带预计耗时，标出哪些能同时做、哪些得守着灶 |

**AI 的结果只填表单，不直接入库。** 它认错用量是常事，所以最后保存永远由你点「保存」触发。

### 它不会替你管菜单

这一版把原来那个「💬 问问 AI」全局对话助手**整个拆掉了**。原因是它越权太多：
一边要读你整个菜单当上下文，一边能直接加菜、下点餐、排计划、记库存 ——
一个认错菜名的回答，代价是往你家菜单里塞一道不存在的菜。

现在 AI 只做一件事：**帮你把一份菜谱**（照片或文字）**变成填好的表单**。

- 它**不知道你家已经有哪些菜** —— 所以它也不会替你「加一道重复的菜」，因为你根本没让它加
- 它**改不动**点餐、库存、本周计划、留言、家庭成员 —— 那些只能你在对应页面里点
- 它**不知道**当前是哪个家庭、你是谁 —— 它拿不到这些，也不该拿

省下来的不只是风险，还有每轮对话要塞进去的菜单上下文：那部分 token 和等待时间没有了。

### 📋 粘贴文字这条路的典型用法

从别处抄来的菜谱往往是一大段话。点「📋 粘贴文字，AI 帮我写」展开一个文本框，
把整段粘进去，它会拆成：菜名、分类、份量、耗时、难度、通用调料、每种做法各带自己的调料。

适合这些场景：微信里别人发你的、公众号图文、外卖平台的、下馆子拍照后记下来的。
嫌它拆得不好就直接改 —— **它填的每个格子都还是普通输入框**。

### 厨房助手给的是时间轴，不是一张单子

点「👨‍🍳 厨房助手」等几秒，出来的是一条按分钟排好的流程，比如：

```
⏱ 备餐流程 · 大约 55 分钟

T+0′   8 分钟   🥬 洗切配菜           🟢 可离开 · 和别的菜同时做
       💡 这段时间灶是空的，把三道菜的配料一次切完最划算
T+8′   7 分钟   🥩 腌五花肉            🟢 可离开 · 腌的时候去调碗汁
T+15′  3 分钟   🥚 打蛋液             🔴 要守灶 · 离不了
T+18′  5 分钟   🍳 番茄炒蛋上桌        🔴 要守灶 · 离不了
T+23′  …        （后面的步骤接着往下排）
```

- **T+N′ 是从点开始算的累计分钟**，不是每步自己花多久——照着时间看表就行
- 🟢 **可离开**：这步在案板上/腌着/炖着，灶空着，顺手做别的去
- 🔴 **要守灶**：炒、蒸、煮，这几分钟走不开
- 💡 一句话说明为什么这么排，不喜欢就当没看见
- 顶部「大约 N 分钟」是整条流程的总长，用来估「几点能吃上」

它排的是**今晚这几道菜**，不是一周的备餐计划——想周末集中备货还是用「🗓️ 计划」那一页。

### 怎么开启

新建 `data/ai.json`：

```json
{
  "enabled": true,
  "baseUrl": "https://api.minimaxi.com/v1",
  "model": "MiniMax-M3",
  "apiKey": "你从 MiniMax 控制台拿到的 Key",
  "timeoutMs": 45000,
  "maxCompletionTokens": 8000
}
```

- **国内站**用 `api.minimaxi.com`，**国际站**用 `api.minimax.io`。填错了会直接报「API Key 不对」。
- 也支持环境变量 `MINIMAX_API_KEY` / `MINIMAX_BASE_URL` / `MINIMAX_MODEL` / `MINIMAX_TIMEOUT`，环境变量优先于文件。
- **没配 Key 时，整个 AI 入口直接不显示**——与其点了才报错，不如一开始就不给入口。
- 改完 `ai.json` 重启服务生效。管理页 → 家庭设置 → 「🤖 AI 助手」能看到当前状态。

### 钱和隐私

- **花的是你自己的额度**，调用一次大约几分钱到几毛钱。实测：看图 4~6 秒、厨房调度 5 秒左右。
- 设了管理口令的话，AI 调用也要口令——毕竟每次调用都是你掏钱。
- `data/ai.json` 已被 `.gitignore` 双重排除，**永远不会传到 GitHub**；Key 只留在服务端，
  `GET /api/state`、导出备份、前端 JS 里都没有它。
- **Key 是你的密钥**，填在对话里或者贴到公开地方等于送人，记得在 MiniMax 控制台定期轮换。

### AI 挂了不影响别的

没 Key、断网、超时、额度用完——点餐、库存、本周计划、买菜清单全部照常工作。
AI 只是个可选的加速器，不是必需品。

## 十二、看看自己是哪一版

### 在哪看

管理页（底部第六个页签「🧺 管理」）最底下有「关于」区块：

- **当前版本号**，旁边一列
- 点版本号（或点「📜 更新内容」）打开**更新日志**，往下列着每个版本改了什么
- 当前版本那一行高亮，看一眼就知道自己跑的是不是最新的

### 为什么版本号写在服务端

更新日志写在 `server.js` 的 `RELEASES` 里，不是单独的文件——打包时不会漏文件导致日志空白。

改版本时同步修改 `server.js` 顶部的 `APP_VERSION` 和 `package.json` 的 `version`，
再往 `RELEASES` 数组最前面加一条。发布脚本会在提交前检查这两个版本号是否一致。

### 发布一次更新

在项目目录运行：

```bash
npm run publish
```

脚本会依次运行语法检查和接口自检，重新生成
`E:/code/家庭菜单/package/家庭菜单-便携版/` 及 ZIP，然后只提交应用文件并推送当前分支到 `origin`。
本地数据、照片、备份和临时脚本不会被自动提交。提交说明可以这样覆盖：

```powershell
$env:PUBLISH_MESSAGE = 'feat: 更新家庭菜单权限'; npm run publish
```

### 家人不用管这个

版本信息在管理页里，只有开管理的人看得到；`GET /api/version` 本身也不需要口令，
因为它不含任何家庭数据——你随时都能确认自己跑的是哪一版。

## 十三、常见问题

**手机打不开这个地址**
- 确认手机和电脑连的是同一个 WiFi（不是一个用流量一个用 wifi）
- Windows 防火墙第一次启动时会弹窗，要点「允许访问」
- 路由器开了「AP 隔离 / 访客网络」时，同网设备之间互不可见，需要在路由器里关掉

**端口被占用**
`set PORT=8888 && node server.js`，然后访问 `http://localhost:8888`

**切错家庭了 / 别人的手机显示的是我选的家庭吗**
不会。每个浏览器各记各的选择。想强制改：浏览器设置里清掉本站数据，或者点开切换器重新选。

**想改菜谱但忘了口令**
编辑 `data/settings.json`，把 `adminPin` 改成 `""` 再重启服务

**AI 入口不见了**
说明 `data/ai.json` 没配好或者 `enabled` 不是 `true`。管理页 → 家庭设置 → 「🤖 AI 助手」那行会显示当前状态。
配好了还没显示的话重启一次服务。

**找不到「问问 AI」的入口了**
对，v1.9.0 起那个全局对话助手已经删掉了。现在 AI 只在三个地方出现：
菜品编辑器里的**「📷 拍张照」/「📋 粘贴文字」**、菜品编辑器底部的**「🧹 整理规范」**、
点餐页的**「👨‍🍳 厨房助手」**。理由见第十节「它不会替你管菜单」。

**AI 报「API Key 不对」**
`baseUrl` 和 Key 的站点对不上。国内站 `api.minimaxi.com`，国际站 `api.minimax.io`，换错了就是 401。

**菜品误删了**
管理页「恢复备份」；或者直接改 `data/dishes.json`。服务会把解析失败的 JSON 自动备份成
`dishes.json.corrupt-时间戳`，不会把你的原始文件冲掉。

**批量删错了（库存 / 点餐 / 计划 / 菜品）**
只能靠管理页「恢复备份」——删掉的行不会留在数据文件里。
所以删之前一定要看那句确认弹窗：它会念出**前三个**名字，超过三个就补一句「等 N 样」，
确认名字跟你想删的一致再点。改保质期、改分类、改标签这些是更新不是删除，点错了改回来就行。

**点餐 / 计划被批量删了**
同上，走管理页「恢复备份」。每份备份里有当天的 `orders.json` / `plans.json`，
点一下就回到打备份那一刻的样子。

**「全选」为什么只选了 10 样，我库存里有 12 样**
因为筛选着。筛了「临期」就只全选当前看得见的那些，「已选 N / M」的 M 也跟着变。
退出筛选再全选才是全部。

## 十四、目录结构

```
server.js        服务端（原生 http，零依赖）
public/
  index.html     页面骨架
  styles.css     样式
  app.js         前端逻辑
data/            数据（自动创建）
  ai.json        AI 配置（只在你自己电脑上，绝不入库）
uploads/         图片（自动创建）
backups/         自动快照（服务自己写的，不进便携包）
start.bat        Windows 一键启动
build-package.js 打包便携版
publish-update.js 一键发布：自检 + 打包 + 提交 + 推送
_selftest.js     接口自检（448 项，在临时目录跑，不碰真实数据）
_packtest.js     打包产物冷启动验证（node build-package.js 之后跑）
_memtest.js      内存基准：全内存打包 vs 流式打包
_memrun.js       内存基准端到端：起真服务走真接口（临时目录，不碰真实数据）
```

## 十三·五、自己跑一遍自检

```bash
node --check server.js && node --check public/app.js
node _selftest.js      # 448 项；在系统临时目录起独立实例，绝不碰 data/
node build-package.js && node _packtest.js
```

自检会在临时目录里造自己的数据、起自己的服务、自己收摊。跑一百遍也不会动你 `data/` 里的一个字节。
