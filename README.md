# 家庭菜单 · 本地点餐服务

一个跑在自己电脑上的家庭菜单 + 点餐 + 库存 + 本周计划服务。把常做的菜录进去
（分类、做法、调料用量、图片、步骤、备注），家里人用手机连同一个 WiFi 打开网页就能点餐，
做饭的人看到点餐单和自动汇总的买菜清单；周末还能把想做的菜排进「本周计划」，照着汇总单一次买齐。

**一份菜谱，所有家庭共享；点餐、库存、本周计划，每个家庭各记各的。**
家庭可以用房号（301）、门牌（西苑 2 栋 501）或者随便起的称呼来命名。

**零第三方依赖**，不需要数据库、不需要 `npm install`，有 Node.js 就能跑。

想让它更省事，可以接上你自己的 MiniMax 账号：**顶栏随时问它**（**走到哪个页面都能问，它知道你正在看什么**）、
**拍张照自动写菜谱**、**把乱菜谱整理规范**、**厨房助手排一整晚的备餐时间轴**（见第十节，不配也完全不影响使用）。

## 一、启动

### 方式 A：双击（Windows）

双击 `start.bat`。命令行窗口会显示访问地址：

```
  本机访问：   http://localhost:8787
  手机访问：   http://192.168.x.x:8787   ← 家人连同一个 WiFi 打开这个
```

**这个窗口要一直开着**，关掉服务就停了。

### 方式 B：命令行

```bash
node server.js
# 或者
npm start
```

换端口：`set PORT=8888 && node server.js`

### 前置条件

装了 [Node.js](https://nodejs.org/zh-cn)（LTS 版本即可，16 以上都行）。
检查：`node -v`

## 二、家里人怎么用

1. 手机连上和电脑**同一个 WiFi**
2. 浏览器打开启动窗口里显示的「手机访问」地址
3. 首页是菜单，点开任意一道菜看做法和调料
4. 点右下角 **「今天想吃这个」** → 选自己的头像、填人数、备注 → 提交
5. 做饭的人打开「点餐」页，能看到待做清单、逐道开做/完成，还有**自动汇总的买菜清单**（可以勾掉已买的，也可以一键复制发到家庭群）
6. 菜齐了要动手了，点一下 **「🔥 一键开做」**，待做的全部转成制作中；每道菜做完点「完成」

周末想提前备菜，打开「🗓️ 计划」页把这周要做的菜排上，**一次买齐**里就是照着买的清单。

想让家人免登录收藏：手机浏览器「添加到主屏幕」，图标和 App 一样。

### 一键开做

点餐页顶部有 **「🔥 一键开做 N」**（N = 当前待做数量），和「👨‍🍳 厨房助手」并排。

- 有待做菜时才出现，点一下**所有待做的一起转成制作中**，不用一道道点
- 转完之后页面自动切到「制作中」，接着逐道点「完成」就行
- 下过厨的应该不用一道道点「开做」，这个按钮就是为这个场景省事的
- 删菜、记菜、管理入口都还在原处，没被挪走

## 三、多个家庭

### 加一个家庭

点顶栏右上角的 **「🏠 名字 ⌄」** 按钮 → 「＋ 添加家庭」。名字可以是：

- 房号：`301`、`502`
- 门牌：`西苑 2 栋 501`
- 称呼：`外婆家`、`单身公寓`

还能挑个图标、填一句备注（住哪、几口人）。

### 怎么分的

| 内容 | 是否共享 |
| --- | --- |
| 菜品、分类、做法、图片 | **全体共享**，录一次所有家庭都能用 |
| 点餐单 / 买菜清单 / 买菜记录 | **按家庭分开** |
| 库存（食材、数量、保质期） | **按家庭分开** |
| 本周计划 | **按家庭分开**，各家这周各自安排 |
| 家庭成员、头像 | **按家庭分开**，各管各的 |

### 切换家庭

顶栏那个按钮就是切换器，弹层里能看到每个家庭当前的「几位家人 · 几道待做 · 几样库存 · 几样要处理」，
点一下就切过去。

**每台设备记住自己选的是哪个家庭**（存在浏览器本地），
所以 A 家手机上固定在 `301`、B 家手机上固定在 `502`，互不干扰；同一台电脑开两个浏览器也可以各选各的。

### 管理家庭

管理页 →「家庭」区块：重命名、换图标、删除。
删除一个家庭会连它名下的点餐、库存和本周计划一起清掉（会先弹窗告诉你各有多少条）。

> 至少会保留一个家庭，删不掉最后一个。

## 四、库存（家里有什么食材）

底部第四个页签「🧊 库存」，**每个家庭一本独立的账**。

### 能记什么

食材名、分类、数量 + 单位、保质期到哪天、备注。
分类覆盖了家里会囤的东西：

> 肉类 · 蛋类 · 奶制品 · 蔬菜 · 水果 · 主食粮油 · 豆制品 · 水产海鲜 · 冷冻食品 · 饮料 · 调味干货 · 零食 · 其他

### 录入

点右下角「＋ 记一样食材」：

- **常见食材快选** —— 内置 148 种常见食材（猪里脊、鸡蛋、纯牛奶、黄瓜、可乐、蚝油……），
  按分类列出，点一下自动填好名字、分类、单位，还有**参考保质期**（鸡蛋 20 天、可乐 180 天、青菜 3 天…）
- 也可以直接搜索，或者自己输入表里没有的
- 保质期除了日期框，还有「明天 / 3 天 / 一周 / 一个月」快捷按钮

### 看和改

- 按分类分组，分类顺序固定（肉→蛋→奶→菜…），同分类里快过期的排最前
- 数量直接用 `−` `＋` 调；称重的按大份走（g 一次 50、kg/斤 一次 0.5），论个的一次 1
- 保质期徽标四档：**已过期**（红）→ **今天到期**（橙）→ **3 天内**（橙）→ **还剩 N 天**（绿）→ **未填保质期**（灰）
- 顶部有临期/过期汇总卡片和红色提醒条，一键「看看」筛选、一键「清理」批量删掉
- 底部页签上的红色角标 = 这个家庭有几样该处理了

### 批量删除

上面那个「清理」只管临期的那批，平时整理库存想一次删好几样，用批量删除：

1. 点库存页顶部的 **「☑ 批量删除」** 进入多选（右下角的「＋ 记一样食材」会先让位，避免误触）
2. 每行前面变成勾选框，勾上要删的；顶栏有 **「☐ 全选 / 已选 3 / 12 / 退出 / 🗑 删除」**
3. 「全选」选中的是**当前能看到的**那些（筛了「临期」就只全选临期的），「已选 N / M」里的 M 也跟着变，不会出现「全选了 10 样却删掉 12 样」
4. 点「🗑 删除」会弹窗确认，**写清楚要删哪几样**，确认后一次删完

批量删除是**不可撤销**的（想找回只能去管理页恢复备份）。别拿它清空整个库存用——真要清空就一条条划，偶尔手滑一次代价太大。

### 和买菜清单联动

点餐页的买菜清单里：

- **家里已有的会标出来** —— `🏠 家里有 4个`，不用买
- **家里没有的给个「入库」按钮** —— 买回来点一下，数量和单位会从菜谱用量自动解析（比如「1 小勺」直接记成 1 小勺），记进当前家庭的库存

> 不会自动扣减库存：菜谱写的是「2 个」，库存记的是「400g」，两个单位对不上，
> 自动算只会算错。所以改成「显示家里有多少 + 人工点入库」。

## 五、本周计划（一次买齐）

底部第二个页签「🗓️ 计划」。**先想好这周做哪几道菜，再照着单子一次把菜买齐。**

菜单页顶部也有一张「🗓️ 本周计划」入口卡片，两个地方都能进。

### 怎么把菜排进来

三条路都行：

| 入口 | 怎么用 |
| --- | --- |
| 菜品详情页 | 点开任意一道菜 →「＋ 加入计划」，加完按钮变「✓ 已在计划里」 |
| 计划页右下角 | 「＋ 加一道菜」→ 从菜谱里挑，或者自己写一道菜单里没有的 |
| 菜单页顶部 | 「🗓️ 本周计划」卡片直接进计划页 |

份量会自动从菜谱带过来（「2 人份」「3 碗」），不用重填。

> 同一道菜一周内只排一次，重复加会被拦下并提示。菜谱删了也不影响已经排好的计划——
> 计划里存的是菜名快照。

### 一次买齐

计划页下半部分是**照着单子采购**的汇总：

```
一次买齐
15 样待买 · 15 样家里没有          [复制清单]

✓ 番茄     番茄炒蛋 2 个                    [入库]
✓ 白糖     番茄炒蛋 1 小勺 · 宫保鸡丁 1.5 勺  [入库]
✓ 鸡腿肉   宫保鸡丁 400g                    [入库]
✓ 生抽     宫保鸡丁 2 勺 · 拍黄瓜 1 勺        [入库]
...
```

- **多道菜用到的同一味料会合并成一行**，后面写清分别是哪几道菜要用
- **家里已有的会标出来**，和买菜清单一个逻辑
- **「入库」按钮**：买回来点一下，数量单位从菜谱用量自动解析，直接记进当前家庭的库存
- **「复制清单」**：整张单子复制走，发家庭群或者抄在纸上

> 只统计**菜谱里有的**菜。自己随手写的一道菜没有调料用量，混进来只会显示一堆没意义的空行。

### 翻周

计划页顶上有一条 `‹ 10月12日 - 10月18日 ›`，左右箭头翻上一周/下一周，
中间显示「本周」「下周」或者具体日期。

**一周从周一开始算**。周三加的菜会自动归到本周一那一栏。

空的一周显示「这一周还没安排」，可以直接开排。
「清空这一周」只清当前这一周，不会动别的周。

### 和点餐的区别

| | 本周计划 | 点餐 |
| --- | --- | --- |
| 什么时候用 | 周末看「这周吃什么」，提前买菜 | 今天谁要吃 |
| 按什么分 | 按**周** | 按**人** |
| 采购清单 | 按整个计划的菜汇总 | 按点餐（可以只筛某个人）汇总 |

两个页签各自独立，最后都能出买菜清单。

## 六、家庭成员 / 按人分餐

### 登记成员

管理页 →「家庭成员」→ ＋添加。注意这里是**当前选中的那个家庭**的成员，
想改别的家庭，先切过去再改。

### 点餐单按家人分组

点餐页默认就是**按家人分组**的，每组头部直接写清这人要吃几道、共几份：

```
👨 爸爸        1 道 · 共 3 份
   宫保鸡丁

👩 妈妈        2 道 · 共 4 份
   拍黄瓜、番茄炒蛋
```

分餐、分装饭盒照着分就行。想看时间顺序，点右上角「⇅ 改成按时间」切回去。

### 只看某一个人

点餐页有一排成员头像胶囊，点一下就只看 TA 的点餐——**买菜清单也跟着过滤**，
只看妈妈时就只列妈妈那几道菜要用的料。

### 成员统计

管理页每个成员后面显示「点过 N 次 · 共 M 份」，看看谁最捧场。

> 删除成员不会删掉 TA 走过的点餐记录，只是分组显示时不再有专属头像。

## 七、菜谱能记什么

| 字段 | 说明 |
| --- | --- |
| 菜名 / 分类 | 分类可自由增删改名，比如「家常菜」「主食」「凉菜」 |
| 一句话介绍 | 卡片上显示，家人一眼认出 |
| 图片 | 多张，第一张做封面；上传时自动压缩到 1400px，不用担心占空间 |
| 份量 / 耗时 / 难度 | 「2-3 人份」「30 分钟」「简单」 |
| 标签 | 下饭、快手、宴客……搜索也能搜到 |
| **通用调料** | 名称 + 用量，**每种做法都要用**的那些，会汇总进买菜清单 |
| **做法步骤** | 一行一步，支持一菜多做法（家常版 / 快手版），**每个做法能带自己独有的调料**（见下） |
| **备注** | 经验、禁忌、替换方案（比如「花生最后放，久炒会软」） |
| 拿手菜标记 | 显示星标 |

### 一道菜多种做法，各自带各自的调料

一道菜红烧、清蒸、微辣往往差着几味料。与其把调料全堆在菜品上、然后分不清哪个做法要哪些，
不如分两层记：

| 记在哪 | 什么时候用 |
| --- | --- |
| 菜品的**通用调料** | 每种做法都要用的。糖、盐、酱油、主料这些 |
| 每个**做法里的调料** | 只有这个做法额外要的。微辣版多一勺小米椒，清蒸版多一把葱姜 |

编辑菜谱时，每个做法卡片里有一块 **「这个做法独有的调料 —— 上面的通用调料它也能用，这里只写它额外要的」**，
点「＋ 加一味」往下加即可；点调料行右边的 ✕ 删掉。

菜品详情页里，通用调料单独立一块，下面每个做法底下再单独列出它自己那几味。

买菜清单会**把通用调料和各做法的调料一起汇总**，并写清来自哪道菜的哪个做法：

```
蒜        拍黄瓜（快手版） 3 瓣 · 孜然牛肉（微辣版） 4 瓣
小米辣    孜然牛肉（微辣版） 1 勺
```

> **老菜谱不用动。** 以前记的做法没有这一层字段，打开时自动补成空，你原来记的用量和步骤一样都不会少。
> 以前记在菜品上的调料，继续当「通用调料」用就行。

## 八、数据存在哪

```
data/
  dishes.json       菜品
  categories.json   分类
  households.json   家庭（含各家的成员）
  orders.json       点餐记录（带 householdId）
  pantry.json       库存（带 householdId）
  plans.json        本周计划（带 householdId + weekOf）
  settings.json     店名、欢迎语、管理口令
uploads/            图片文件
```

纯文本 JSON，随时可以自己看、可以手动改。

**换电脑 / 重装系统前**：管理页 →「⬇ 导出备份」，会下载一个 `menu-backup-YYYY-MM-DD.zip`
（里面是 `backup.json` + `uploads/` 全部照片）。新机器上「⬆ 恢复备份」把这个 zip 选进去就行，
菜谱和照片一起回来。

> 想加一道新菜前，先导出一份，养成习惯。

### 从老版本升级

第一次跑新版本时会自动迁移，不用手动改任何东西：

- 没有 `households.json` → 自动建一个默认家庭「我家」
- 老版本 `settings.json` 里的家庭成员 → 搬进第一个家庭
- 没有 `householdId` 的历史点餐 → 归到第一个家庭
- 没有 `plans.json` → 自动建空文件
- 重复 id、坏 JSON → 自动去重 / 备份成 `.corrupt-时间戳`，不丢原始文件

### 数据存在哪、断了怎么办

```
data/       菜谱、分类、家庭、点餐、库存、计划（纯文本 JSON）
uploads/    菜品照片
backups/    自动快照（服务自己写的，别手动改）
```

写入是**原子的**：先写 `.tmp` 再改名覆盖，断电不会留下半截 JSON。
正常关停（Ctrl+C、systemd stop）会把内存里的改动全量刷盘。
最坏情况是 `kill -9` 或拔电，**只丢最后 0.15 秒内的改动**。

**别让新旧两台机器同时跑同一个 `data/` 目录** —— 两边都会全量覆盖，会打架。

## 八·五、备份（数据出事时的后悔药）

### 自动快照

服务**每次启动**、以及**每天凌晨 3 点**自动打一份快照到 `backups/`，保留最近 7 份。

管理页 →「数据」区里就一行，不用去数：

```
⬇ 导出备份            ⬆ 恢复备份

🗂️ 自动备份                          💾  ↩
   已自动存 5 份，保留最近 7 份，在 backups/ 目录
```

- **⬆ 恢复备份** —— 就是**选一个备份文件**（导出时下的那个 zip），整个库回到那一刻的状态。
  这是恢复数据的主路径，选文件就行，不用在一列快照里翻
- **💾** —— 改重要东西之前先点一下，立刻手动存一份（比等凌晨三点靠谱）
- **↩** —— 「回到最近一次自动备份」，一键回退。会弹窗说清楚**这之后的改动会没**，确认了才动

手动存的和自动存的放在同一个 `backups/` 目录里，一共留 7 份，旧的自动清掉。

> 快照里含有管理口令明文，所以这些入口都需要口令，没解锁看不到、也点不动。

### 导出备份（换电脑用）

管理页 → 「⬇ 导出备份」，下下来的是一个 **zip**，里面有：

```
backup.json      菜谱、分类、家庭、成员、点餐、库存、计划、设置
uploads/         全部菜品照片
```

新机器上装好、起一次服务，然后管理页 → 「⬆ 恢复备份」选这个 zip 就行。
**老版本导出的纯 JSON 备份也照样能恢复**，不会因为你升级了就打不开。

### ⚠️ 并发限制，先看一眼

这个服务是**单进程 + 整份文件覆盖**，没有版本校验：

| 场景 | 安全性 |
| --- | --- |
| 多人同时**点餐、查库存、看菜单、各自记东西** | ✅ 安全 |
| 两人同时**编辑同一道菜的菜谱** | ❌ 后保存的人会覆盖前一个人的修改 |

日常一家几口人同时用完全没问题。要真正支持「多人同时改同一道菜」，
需要给保存加上版本比对（发现对不上就提示「已被别人改过」），
这个还没做。

### 公网部署要额外做的

默认 `HOST=0.0.0.0`，也就是监听所有网卡。放内网没问题，
但放到有公网 IP 的服务器上时，**务必**：

1. 在管理页设一个 `adminPin`（不然谁都能改你的菜谱）
2. 用 `set HOST=127.0.0.1` 让它只监听本机，前面挂 Nginx 反代并配 HTTPS
3. 用 systemd 托管，别裸跑 `node server.js`（SSH 一断进程就没了）

## 九、加个管理口令（可选）

管理页 → 家庭设置 → 管理口令。填了之后，进入「管理」页需要输口令，
家里人只能看菜单、点餐、改自己的库存，改不了你的菜谱和家庭列表。留空就是不锁。

> 切换家庭本身不锁——局域网内信任这个前提，谁切都行。

### 它是真的锁，不是装样子的

口令**只存在服务端**，前端永远拿不到明文；解锁时服务端发一枚会话 token（12 小时自动过期），
之后改菜谱、改家庭、导出备份都要带这枚 token。没带就一律 401。

具体挡住这些：

| 操作 | 没口令时 | 设了口令后 |
| --- | --- | --- |
| 改菜谱 / 分类 / 家庭 | 随便改 | **要口令** |
| 导入备份 | 随便导 | **要口令** |
| 导出备份（含口令明文） | 随便导 | **要口令** |
| 上传图片 | 随便传 | **要口令** |
| 点餐、记库存、排本周计划 | 随便用 | **照样随便用** ← 家人的日常功能不被挡 |

所以局域网里别人拿手机扫你电脑的地址，最多只能点餐和改自己的库存，改不了你的菜谱。

### 改口令 / 取消口令

- **换口令**：设置页填新值保存即可，旧会话立刻全部失效
- **取消口令**：设置页勾上「取消口令保护」再保存
- **忘了口令**：改 `data/settings.json`，把 `adminPin` 改成 `""` 再重启服务

口令只加锁管理区，**不影响已保存的数据**，随时能关。

## 十、AI 厨房助手（可选，接你自己的 MiniMax）

四个能力，都跑在你自己的 MiniMax 账号上，不经过任何第三方：

| 入口 | 在哪 | 干什么 |
| --- | --- | --- |
| 💬 问问 AI | **顶栏，任何页面** | 直接跟它说话问事，它知道你正在看什么 |
| 📷 拍张照，AI 帮我写这道菜 | 新增 / 编辑菜品 | 拍一张成品照，自动填菜名、分类、通用调料、步骤 |
| 🧹 让 AI 把这份菜谱整理规范 | 新增 / 编辑菜品 | 把随手记的乱菜谱理顺：「够两个人吃的」→「2 人份」 |
| 👨‍🍳 厨房助手 | 点餐页（待做 ≥ 2 道时出现） | 把今晚几道菜排成一条**备餐时间轴**：从「开始洗菜」到最后一道上桌，每步带预计耗时，标出哪些能同时做、哪些得守着灶 |

**AI 的结果只填表单，不直接入库。** 它认错用量是常事，所以最后保存永远由你点「保存」触发。

### 💬 顶栏那个气泡：走到哪都能问

菜单、库存、点餐、计划、管理——**每个页面顶上都有这个 💬，点开就能问**，
不用先跳去某个特定页面。它每次都会先看一眼你现在的处境：

| 它知道的 | 例子 |
| --- | --- |
| **当前在哪一页** | 「现在在点餐页」 |
| **当前是哪个家庭** | 「我家，1 位家人，4 道待做」 |
| **手上这道菜** | 你正开着宫保鸡丁，它知道你在问这道菜 |
| **谁点了什么** | 4 条待做点餐、各是谁点的、几份 |
| **哪些食材快过期了** | 只给临期和已过期的那些，不是把整个库存倒给它 |

所以可以直接问「今晚吃啥」「孜然牛肉怎么做」「冰箱里还有没有快坏的菜」，
它答的时候手里是有数据的，不是泛泛而谈。

- 输入框**回车即发**，底下还有快捷指令胶囊
- **清空对话** 随时从头再来
- 它只带最近 12 轮上下文，早先的不会无限累积
- 没配 Key 时这个按钮**根本不显示**，不会给你一个点了就报错的入口

> 问归问，**改数据还得你自己动手**。它不会替你删菜、不会替你下单，
> 想让它帮你调整点餐单，它会告诉你怎么调，最后由你点。

### 厨房助手给的是时间轴，不是一张单子

点「👨‍🍳 厨房助手」等几秒，出来的是一条按分钟排好的流程，比如：

```
⏱ 备餐流程 · 大约 55 分钟

T+0′   8 分钟   🥬 洗切配菜           🟢 可离开 · 和别的菜同时做
       💡 这段时间灶是空的，把三道菜的配料一次切完最划算
T+8′   7 分钟   🥩 腌五花肉            🟢 可离开 · 腌的时候去调碗汁
T+15′  3 分钟   🥚 打蛋液             🔴 要守灶 · 离不了
T+18′  5 分钟   🍳 番茄炒蛋上桌        🔴 要守灶 · 离不了
T+23′  …        （后面的步骤接着往下排）
```

- **T+N′ 是从点开始算的累计分钟**，不是每步自己花多久——照着时间看表就行
- 🟢 **可离开**：这步在案板上/腌着/炖着，灶空着，顺手做别的去
- 🔴 **要守灶**：炒、蒸、煮，这几分钟走不开
- 💡 一句话说明为什么这么排，不喜欢就当没看见
- 顶部「大约 N 分钟」是整条流程的总长，用来估「几点能吃上」

它排的是**今晚这几道菜**，不是一周的备餐计划——想周末集中备货还是用「🗓️ 计划」那一页。

### 怎么开启

新建 `data/ai.json`：

```json
{
  "enabled": true,
  "baseUrl": "https://api.minimaxi.com/v1",
  "model": "MiniMax-M3",
  "apiKey": "你从 MiniMax 控制台拿到的 Key",
  "timeoutMs": 45000,
  "maxCompletionTokens": 8000
}
```

- **国内站**用 `api.minimaxi.com`，**国际站**用 `api.minimax.io`。填错了会直接报「API Key 不对」。
- 也支持环境变量 `MINIMAX_API_KEY` / `MINIMAX_BASE_URL` / `MINIMAX_MODEL` / `MINIMAX_TIMEOUT`，环境变量优先于文件。
- **没配 Key 时，整个 AI 入口直接不显示**——与其点了才报错，不如一开始就不给入口。
- 改完 `ai.json` 重启服务生效。管理页 → 家庭设置 → 「🤖 AI 助手」能看到当前状态。

### 钱和隐私

- **花的是你自己的额度**，调用一次大约几分钱到几毛钱。实测：看图 4~6 秒、厨房调度 5 秒左右。
- 设了管理口令的话，AI 调用也要口令——毕竟每次调用都是你掏钱。
- `data/ai.json` 已被 `.gitignore` 双重排除，**永远不会传到 GitHub**；Key 只留在服务端，
  `GET /api/state`、导出备份、前端 JS 里都没有它。
- **Key 是你的密钥**，填在对话里或者贴到公开地方等于送人，记得在 MiniMax 控制台定期轮换。

### AI 挂了不影响别的

没 Key、断网、超时、额度用完——点餐、库存、本周计划、买菜清单全部照常工作。
AI 只是个可选的加速器，不是必需品。

## 十二、看看自己是哪一版

### 在哪看

管理页（底部第五个页签「⚙️ 管理」）最底下有「关于」区块：

- **当前版本号**，旁边一列
- 点版本号（或点「📜 更新内容」）打开**更新日志**，往下列着每个版本改了什么
- 当前版本那一行高亮，看一眼就知道自己跑的是不是最新的

### 为什么版本号写在服务端

更新日志写在 `server.js` 的 `RELEASES` 里，不是单独的文件——打包时不会漏文件导致日志空白。

改版本就改两处：`server.js` 顶部的 `APP_VERSION` 和 `package.json` 的 `version`，
再往 `RELEASES` 数组最前面加一条。

### 家人不用管这个

版本信息在管理页里，只有开管理的人看得到；`GET /api/version` 本身也不需要口令，
因为它不含任何家庭数据——你随时都能确认自己跑的是哪一版。

## 十三、常见问题

**手机打不开这个地址**
- 确认手机和电脑连的是同一个 WiFi（不是一个用流量一个用 wifi）
- Windows 防火墙第一次启动时会弹窗，要点「允许访问」
- 路由器开了「AP 隔离 / 访客网络」时，同网设备之间互不可见，需要在路由器里关掉

**端口被占用**
`set PORT=8888 && node server.js`，然后访问 `http://localhost:8888`

**切错家庭了 / 别人的手机显示的是我选的家庭吗**
不会。每个浏览器各记各的选择。想强制改：浏览器设置里清掉本站数据，或者点开切换器重新选。

**想改菜谱但忘了口令**
编辑 `data/settings.json`，把 `adminPin` 改成 `""` 再重启服务

**AI 入口不见了**
说明 `data/ai.json` 没配好或者 `enabled` 不是 `true`。管理页 → 家庭设置 → 「🤖 AI 助手」那行会显示当前状态。
配好了还没显示的话重启一次服务。

**顶栏的 💬 问不了菜谱**
它只会读你当前的家庭数据，**不会凭空造菜谱**。要它帮你写一道新菜，得在「新增 / 编辑菜品」里用
📷 拍张照 或 🧹 整理规范，这两个才是往菜谱里写东西的。

**AI 报「API Key 不对」**
`baseUrl` 和 Key 的站点对不上。国内站 `api.minimaxi.com`，国际站 `api.minimax.io`，换错了就是 401。

**菜品误删了**
管理页「恢复备份」；或者直接改 `data/dishes.json`。服务会把解析失败的 JSON 自动备份成
`dishes.json.corrupt-时间戳`，不会把你的原始文件冲掉。

**库存批量删错了**
和菜品一样，只能靠管理页「恢复备份」——删掉的行不会留在库存文件里。
所以批量删除删之前一定要看那句确认弹窗，它会把要删的名字一条条列出来。

**「全选」为什么只选了 10 样，我库存里有 12 样**
因为筛选着。筛了「临期」就只全选当前看得见的那些，「已选 N / M」的 M 也跟着变。
退出筛选再全选才是全部。
