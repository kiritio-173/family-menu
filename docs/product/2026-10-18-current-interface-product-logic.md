# 家庭菜单当前界面与产品逻辑说明

版本：1.21.0  
代码基线：提交 5dd584e  
文档日期：2026-10-18  
适用范围：当前网页端界面、账户流程、家庭流程、菜单、点餐、计划、留言、库存和设置管理。

> 本文描述当前代码已经实现的行为。文末单独列出已发现的界面逻辑问题和下一步统一方向，避免把规划内容误认为已经完成。

## 1. 产品定位

家庭菜单是一个面向多个家庭、多成员共同使用的本地菜单系统。系统围绕一条日常链路工作：

~~~text
菜谱 → 计划/点餐 → 做饭状态 → 买菜清单 → 家庭库存
  ↑                                  ↓
  └────── 共享菜复制为自己的私房菜 ──────┘
~~~

系统同时管理三类身份和数据范围：

- **全局账户**：用户登录身份，跨设备、跨家庭保持一致；
- **家庭关系**：账户在某个家庭中的成员或管理员角色；
- **数据归属**：共享数据、某个家庭的私有数据、某个账户创建的菜谱。

账户身份决定“是谁”，家庭关系决定“能看哪个家庭”，菜谱作者决定“谁能改哪道菜”，超级管理员授权决定“能否维护全局平台数据”。

## 2. 登录、注册与账户身份

### 2.1 新设备首次打开

未登录时，顶部栏、底部导航和家庭内容全部隐藏，只显示账户入口：

- 登录：登录 ID + 密码；
- 注册：登录 ID + 密码；
- 登录 ID 支持汉字、字母和数字；
- 注册时登录 ID 可留空，服务端自动生成一个可修改 ID；
- 注册时密码可留空，使用初始密码 123456；
- 页面提示继续使用初始密码存在风险；
- 登录成功后服务端返回账户令牌，设备只保存会话缓存。

设备不是用户身份。清理浏览器、换设备或切换家庭都不应该创建第二个用户；账户身份由服务端账户令牌识别。

### 2.2 全局账户资料

账户包含：

- 登录 ID；
- 账户姓名/显示名；
- 头像；
- 账户密码；
- 全局超级管理员授权状态。

同一个账户在不同家庭中的姓名、头像、登录 ID 和作者名称保持一致。家庭成员关系只记录该账户在当前家庭的角色，不重新设置家庭专属密码。

### 2.3 登录后的默认状态

登录成功后：

- 当前家庭默认为空；
- 不自动进入第一户家庭；
- 不自动进入“我的家庭”；
- 用户可以打开账户首页，选择某个已加入家庭；
- 用户也可以浏览公开家庭目录、查看共享菜单、创建家庭或申请加入。

当前代码在无家庭状态下会把底部“菜单”改名为“共享”，把“设置”改名为“账户”，并禁用计划、点餐、留言和库存入口。共享菜单可只读浏览，其他业务需要先创建或加入家庭。

## 3. 页面外壳和公共操作

### 3.1 顶部栏

登录并进入正常工作区后，顶部栏包含：

- 系统名称和欢迎语；
- 当前家庭按钮：切换家庭、查看家庭图标和家庭名称；
- 当前账户按钮：显示账户头像、姓名和全局账户/超级管理员状态；
- 随机来一道；
- 搜索菜名、调料和标签。

当前家庭按钮只改变数据上下文，不改变全局账户身份。账户按钮打开账户资料、家庭列表、超级管理员授权和退出登录入口。

### 3.2 底部导航

当前代码的底部导航固定为六项：

| 入口 | 当前代码视图 | 主要内容 |
|---|---|---|
| 菜单 | menu | 共享菜、私房菜、菜谱详情、随机来一道 |
| 计划 | plan | 周计划、临时菜、计划采购清单 |
| 点餐 | order | 想吃、待做、制作中、已完成、买菜清单 |
| 留言 | board | 家庭留言、回复、表情和认领 |
| 库存 | pantry | 家庭库存、分类、保质期和批量处理 |
| 设置 | settings/manage | 当前实现中混合了账户、家庭、菜谱和系统管理 |

各入口的角标：

- 计划：本周和下周已安排的菜数；
- 点餐：待做订单数；
- 留言：当天新增留言数；
- 库存：临期和过期食材数，过期时显示警示状态。

## 4. 菜单页

### 4.1 菜单范围

菜单数据按归属分为：

- **共享菜**：householdId 为空，所有可见家庭都能查看；
- **家庭私房菜**：householdId 为某个家庭，只在该家庭显示；
- **无家庭状态**：只显示共享菜，不显示任何家庭私房菜。

菜单页使用统一菜单投影，再叠加筛选条件。筛选顺序为：

1. 当前家庭可见范围；
2. 共享/我家私房筛选；
3. 分类筛选；
4. 搜索关键词；
5. 同名菜折叠。

### 4.2 同名菜折叠

“全部”视图中，如果共享菜和当前家庭私房菜同名：

- 默认显示共享菜；
- 提示当前家庭还有几份同名私房版本；
- 点击“展开”才能查看私房版本；
- “我家私房”视图不折叠，完整显示当前家庭私房菜。

折叠只是展示方式，不会删除或覆盖私房菜。

### 4.3 菜卡操作

有当前家庭时，菜卡可以显示：

- 想吃；
- 我来做；
- 菜品留言；
- 供应状态；
- 打开详情；
- 加入计划；
- 今天想吃这个。

没有当前家庭时，菜卡只显示公开共享菜单和只读提示。

### 4.4 菜品详情

详情页显示：

- 菜名、图片、分类、标签；
- 供应状态；
- 通用调料；
- 各做法独有的调料；
- 做法步骤；
- 备注；
- 成品图；
- 加入计划；
- 点菜；
- 留言；
- 收进我家或编辑入口。

暂停供应的菜仍可查看做法、计划和历史记录，但不能新建点餐；随机来一道默认排除暂停供应菜。

### 4.5 随机来一道

随机功能可以组合筛选：

- 全部可见；
- 共享菜单；
- 我家私菜；
- 分类；
- 标签；
- 今天没做过；
- 排除待做/制作中的菜。

筛选条件同时生效，没有结果时不会自动放宽范围。

### 4.6 当前菜谱编辑权限

当前代码实际规则为：

- 超级管理员可以维护全局菜谱；
- 家庭管理员可以维护共享菜和本家庭私菜；
- 普通成员可以维护作者是自己的家庭私菜；
- 历史菜谱没有作者字段时，当前前端存在放宽编辑的兼容逻辑；
- 共享菜可以通过“收进我家”复制到当前家庭，原菜保持不变。

当前实现与用户希望的“只有作者能编辑别人不能改”仍有差异：家庭管理员目前仍可能看到和使用别人私菜的编辑权。这是待收紧的权限问题。

## 5. 计划页

### 5.1 周计划

计划按家庭和周一日期保存：

- 上一周；
- 本周；
- 下一周；
- 更远的周。

计划项可以是：

- 已有菜谱：保存 dishId、菜名和份量；
- 临时菜名：只有菜名，没有菜谱 ID。

计划中的菜可以打开菜谱详情，也可以单独删除或清空整周。

### 5.2 加一道菜

当前弹层提供两种方式：

1. 从菜单中多选菜谱；
2. 手动输入一道临时菜。

当前已知问题：

- “加进去”按钮主要根据选中的菜谱 ID判断；
- 只输入临时菜名时，按钮可能保持禁用；
- 保存逻辑可能只提交已选菜谱，未提交输入框内容；
- 这是第二张截图中“加不进去”的根因。

### 5.3 计划采购清单

计划页会读取已选菜谱中的通用调料和做法调料：

- 同名调料合并；
- 显示来自哪道菜、哪种做法和用量；
- 当前家庭库存按数量和单位实时比较；
- 库存足够显示“已有”，不足显示“库存不足”和还需补购的数量；
- 无库存或余量为 0 显示“待购买”；
- “适量”、单位不一致或无法比较时显示“需确认”，不强行换算；
- 库存不足和需确认的调料保留“入库”按钮；
- 可以复制采购清单。

没有 dishId 的临时菜不会自动参与调料汇总，因为系统没有可读取的菜谱用量。

## 6. 点餐页

### 6.1 点餐状态

点餐状态分为：

- 待做；
- 制作中；
- 已完成；
- 已取消。

页面可以按成员筛选，并可以按成员分组显示。每条点餐记录包含菜名、点餐人、份数、备注和时间。

### 6.2 点菜权限

已加入当前家庭的普通成员可以：

- 从菜单点菜；
- 表示想吃；
- 认领“我来做”；
- 查看点餐状态；
- 查看买菜清单。

无当前家庭或只浏览公开家庭时不能点菜。

### 6.3 做饭状态权限

当前代码规定：

- 家庭管理员或超级管理员可以把待做改为制作中；
- 家庭管理员或超级管理员可以把制作中改为已完成；
- 管理员可以删除点餐记录；
- 普通成员只能查看状态。

### 6.4 点餐页买菜清单

点餐页会根据待做菜品自动汇总调料：

- 同名调料合并；
- 过滤成员后重新计算清单；
- 显示库存余量、需求量和采购状态；
- 库存不足时显示差额，单位不一致时提示确认；
- 可勾选、复制、批量入库。

采购状态由两部分组成：库存余量实时计算“已有/库存不足/待购买”，成员勾选的“已完成”保存在当前家庭的 shopping-status 中；库存判断优先于已完成状态。

## 7. 留言页

留言属于当前家庭，主要功能包括：

- 发布文字留言；
- 选择贴纸；
- 回复留言；
- 添加或取消表情；
- 认领“我来”；
- 查看菜品相关留言；
- 删除留言或回复；
- 多选批量删除。

留言会显示当前全局账户的姓名和头像。没有当前家庭时，留言入口被禁用，不能写入某个家庭的留言数据。

留言和菜谱编辑权限分开：留言互动不代表拥有菜谱编辑权。

## 8. 库存页

### 8.1 库存归属

库存属于当前家庭：

- 不属于某个账户；
- 不属于某道菜；
- 不跨家庭共享；
- 切换家庭后重新读取当前家庭库存。

库存条目通常包含：

- 食材名称；
- 分类；
- 数量；
- 单位；
- 保质期；
- 备注；
- 所属家庭。

### 8.2 库存页面结构

库存页当前包含：

- 全部；
- 临期；
- 过期；
- 食材分类筛选；
- 库存总数；
- 临期数量；
- 过期数量；
- 食材列表；
- 数量增减；
- 新增食材；
- 编辑食材；
- 删除食材；
- 批量设置保质期；
- 批量改分类；
- 批量删除；
- 清理临期/过期食材。

库存按分类分组，并优先显示过期、今天到期和即将到期的食材。

### 8.3 库存与买菜的关系

当前实现的实际关系是：

~~~text
菜谱调料
  ↓
点餐/计划采购清单
  ├─ 同单位库存足够：显示“已有”
  ├─ 同单位库存不足：显示“库存不足”和差额
  ├─ 无库存或数量为 0：显示“待购买”
  └─ 单位不同/适量：显示“需确认”
             ↓
        写入 pantry
~~~

库存条目数量可以在库存页直接输入，或用加减按钮调整。数量允许为 0，保存后采购页立即重新计算；同名库存只有在单位一致时合计，单位不同不强行换算。

### 9.1 普通成员看到的内容

### 9.4 当前管理页折叠

管理搜索可以模糊匹配成员、菜单、备份、AI、版本等关键词。折叠状态保存在前端状态中。

## 10. 家庭账户与生命周期

### 10.1 创建家庭

创建家庭不需要平台批准：

- 当前账户点击创建家庭；
- 家庭创建成功；
- 创建者自动成为家庭管理员；
- 家庭计入账户有效家庭数量；
- 每个账户最多 5 个有效家庭。

### 10.2 公开家庭目录

无家庭或账户首页可以看到公开家庭目录：

- 家庭名称；
- 图标；
- 公开说明；
- 成员数量；
- 查看共享菜单；
- 申请加入。

未批准加入前，只能查看公开共享内容，不能查看家庭私菜、点菜、留言、计划或库存。

### 10.3 申请加入

申请由当前账户自动识别：

- 申请记录包含账户 ID 和账户显示名；
- 申请人可以申请普通成员或家庭管理员；
- 同一账户对同一家庭只保留一条活动申请；
- 家庭管理员可以批准为成员；
- 家庭管理员可以批准为管理员；
- 家庭管理员可以拒绝；
- 批准后建立家庭成员关系。

申请不再应该要求另填家庭成员姓名或设置家庭专属密码。

### 10.4 切换家庭

账户加入多个家庭后：

- 点击顶部家庭按钮或账户家庭列表；
- 选择一个家庭；
- 当前家庭 ID 作为页面数据上下文；
- 账户姓名和登录状态不变；
- 不需要重新登录或重新认领成员；
- 每个家庭的数据独立加载。

### 10.5 退出家庭

当前规则：

- 普通成员可以退出；
- 退出只删除当前账户在该家庭的成员关系；
- 不影响全局账户；
- 不影响其他家庭；
- 退出后清空当前家庭选择；
- 唯一管理员不能留下一个没有管理员的多人家庭；
- 最后一名成员不能直接退出，应该使用解散家庭。

### 10.6 解散家庭

最后一名成员且为管理员时，设置页显示“解散家庭”：

- 二次确认；
- 删除该家庭成员关系；
- 删除该家庭的点餐、库存、计划、留言和私有菜谱；
- 清理加入申请和旧家庭会话；
- 共享菜不受影响；
- 全局账户保留；
- 其他家庭不受影响；
- 成功后默认回到账户首页且不选择家庭。

## 11. 权限模型（当前实现）

### 11.1 全局超级管理员

超级管理员授权：

- 通过全局管理口令获得；
- 绑定当前账户；
- 有效期 12 小时；
- 不随家庭切换失效；
- 可管理所有家庭、共享菜单和系统功能；
- 可使用备份、恢复、导出、AI 和平台设置。

### 11.2 家庭管理员

家庭管理员由家庭成员关系中的 role: owner 决定。当前代码中，家庭管理员可以：

- 审批加入申请；
- 设置家庭成员角色；
- 修改家庭设置；
- 管理共享菜单；
- 管理本家庭私菜；
- 更新做饭状态；
- 执行家庭级管理操作。

当前实现仍把家庭管理员编辑本家庭所有私菜作为允许行为，这与“只有作者能编辑”的目标规则存在差异。

### 11.3 普通成员

普通成员当前可以：

- 浏览当前家庭菜单；
- 查看共享菜和本家庭私菜；
- 编辑自己作者标识的私菜；
- 复制共享菜到本家庭；
- 点菜；
- 排计划；
- 留言；
- 维护库存；
- 标记采购完成；
- 将已购食材入库。

普通成员不能：

- 修改做饭状态；
- 审批成员；
- 修改家庭设置；
- 修改共享菜；
- 在目标家庭之外写入私有数据；
- 使用超级管理员平台功能。

### 11.4 无家庭账户

无家庭账户可以：

- 浏览共享菜单；
- 查看公开家庭目录；
- 查看公开家庭共享菜；
- 创建家庭；
- 申请加入家庭；
- 修改全局账户资料；
- 修改账户密码；
- 申请超级管理员授权。

无家庭账户不能：

- 点菜；
- 排计划；
- 写留言；
- 查看家庭库存；
- 写入库存；
- 维护家庭私菜；
- 管理家庭成员。

## 12. 数据联动关系

### 12.1 菜谱、点餐、计划

- 菜单详情可以加入计划；
- 菜单详情可以直接点菜；
- 计划项可以打开原菜谱；
- 点餐记录可以打开原菜谱；
- 暂停供应菜不能新建点餐；
- 已有计划和历史订单不会因暂停供应自动删除。

### 12.2 菜谱、采购、库存

- 菜谱通用调料和做法调料进入采购汇总；
- 同名调料合并；
- 当前家庭库存匹配同名或包含关系；
- 同单位且库存不少于需求显示“已有”；
- 同单位但库存不足显示“库存不足”和缺口；
- 无库存或余量为 0 显示“待购买”；
- 用量为“适量”或单位不同显示“需确认余量”；
- 入库写入当前家庭 pantry；
- shoppingChecked 只表示成员已买但尚未入库，按家庭保存，普通成员可以操作。

### 12.3 菜谱、共享和私房

- 共享菜是公共只读来源；
- “收进我家”创建独立副本；
- 副本属于当前家庭；
- 副本作者为当前账户；
- 修改副本不改变共享源菜；
- 同名菜在全部视图中可能被折叠；
- 私房视图显示完整私房版本。

## 13. 当前已知问题与界面逻辑缺口

以下问题属于当前实现，不是文档误读：

1. **菜谱管理仍在设置/管理页**：菜单页可以看菜，但新增、编辑、批量导入导出主要集中在管理页，账户、家庭和菜谱操作混在一起。
2. **库存虽然有独立底部入口，但无家庭时会被禁用**：无家庭账户只能看到提示，不能进入库存说明或创建家庭入口。
3. **买菜勾选状态写入全局设置**：普通成员勾选采购清单可能触发管理口令错误。
4. **买菜状态不是完整三状态**：当前实际是库存匹配 + shoppingChecked 勾选，没有独立的“已有/已完成/待购买”资源。
5. **自定义计划菜提交不完整**：输入临时菜名可能不能启用“加进去”，即使输入也可能没有进入批量保存。
6. **家庭管理员菜谱权限偏宽**：当前仍可能编辑本家庭其他人的私房菜。
7. **设置页名称承载过多功能**：账户、家庭、菜谱、系统和备份同时出现，用户难以判断入口。
8. **部分旧文案仍提到家庭口令或成员密码**：当前账户关系已经是主要身份来源，旧提示会造成二次身份确认的误解。
9. **无家庭状态下的账户首页与共享菜单存在跳转关系**：用户可以从账户首页进入共享菜单，但从共享菜单创建/申请家庭的入口需要保持明显。
10. **最后成员解散入口主要位于账户设置**：家庭生命周期动作应在家庭页也可见。

## 14. 下一步统一方向

在不改变账户和家庭核心数据的前提下，建议按以下方向收敛界面：

- 菜谱新增、编辑、复制、批量导入导出全部移动到菜单页；
- 菜单页增加“全部可见 / 我家私房 / 菜谱管理”三个子视图；
- 保留库存作为独立底部入口，不把库存塞进设置；
- 设置页拆成“家庭”和“账户”两个概念；
- 家庭页只放成员、申请、家庭名称、做饭状态、退出/解散；
- 顶部账户按钮只放全局账户和超级管理员授权；
- 采购清单和库存状态改为当前家庭范围保存；
- 将菜谱编辑权收紧为作者和超级管理员；
- 计划弹层允许临时菜单独保存，也允许与菜谱混合保存；
- 无家庭状态继续保留共享浏览、公开家庭目录、创建家庭和申请加入；
- 页面只显示当前账户真正可执行的按钮，服务端继续做最终权限校验。

## 15. 验收用例

### 账户与家庭

- 新设备只出现一次登录/注册；
- 登录后默认没有当前家庭；
- 同一账户切换家庭不重新登录；
- 修改账户姓名后所有家庭同步；
- 账户可以创建、申请加入、退出和解散家庭；
- 最后一名成员可以看到解散入口。

### 菜单

- 共享菜和私房菜显示范围正确；
- 同名私房菜可以展开；
- 共享菜复制后生成家庭私房副本；
- 暂停菜不能新建点餐；
- 管理页和菜单页菜品信息一致；
- 菜谱编辑按钮只对有权限的对象显示。

### 计划与点餐

- 可以选择多道菜加入计划；
- 可以只输入临时菜名加入计划；
- 临时菜和菜谱可以混合加入；
- 点餐状态只有管理员能推进；
- 计划和点餐清单可以复制或入库。

### 库存

- 当前家庭库存不串到其他家庭；
- 可以按分类、临期和过期筛选；
- 数量可以增减；
- 可以从采购清单入库；
- 普通成员入库不应要求超级管理员口令；
- 临期和过期数量显示角标。

### 管理

- 家庭管理员可以处理申请和成员角色；
- 普通成员不能审批成员；
- 超级管理员授权与当前家庭角色分离；
- 平台设置、备份和恢复仅对超级管理员开放；
- 搜索和折叠状态不影响实际权限。

## 16. 结论

当前产品已经形成“全局账户 + 多家庭 + 共享菜/私房菜 + 点餐/计划/库存”的基础结构。现在最需要解决的是界面职责分散：菜谱管理在设置页、库存虽有独立入口但无家庭时完全不可见、采购勾选状态误用全局设置、家庭管理员菜谱权限过宽。

统一后的核心原则是：

~~~text
菜单管菜谱
点餐管吃什么和做饭状态
计划管什么时候做和要买什么
库存管家里有什么
留言管沟通
家庭管成员与家庭关系
账户管身份和超级权限
~~~

## 17. 2026-10-18 修订状态

本次实现已经把采购勾选改为当前家庭范围的 `shopping-status` 资源，普通成员可以标记已买、取消标记和入库；库存数量实时决定“已有”状态。家庭栏目补充家庭广场入口，可浏览其他公开家庭的共享菜并直接收进当前家庭。菜谱编辑权限按作者账户 ID 判断，家庭管理员不再自动获得别人私房菜的编辑权。账户上下文按用户保存并在重新打开网页时恢复，家庭退出、解散或失去访问权限时自动清理。
