# 菜谱原料统一选择设计

日期：2026-10-21

## 目标

让共享菜谱、家庭菜谱、周计划和家庭库存使用同一套全局原料目录，并允许每个家庭补充仅本家庭可见的原料。录入菜谱材料时先选分类/子分类，再选该分类下的原料并填写烹饪用量；原料不存在时可在当前分类中就地新增。菜谱材料不再单独选择“自动判断 / 常备调料 / 需要采购”，计划和库存按原料字典及库存记录确定管理方式。

### 目录作用域与权限

- 全局内置分类和全局子分类对所有家庭可见；家庭管理员可新增全局子分类，新增后所有家庭可见。家庭本地子分类只在所属家庭可见。
- 全局原料对所有家庭可见；家庭管理员可在菜谱或库存添加流程中新增全局原料。家庭本地原料只供所属家庭的菜谱、计划和库存使用。
- 普通家庭成员可选择全局和本家庭原料，并沿用现有家庭字典写入权限新增本地原料；不能创建全局原料、全局子分类或维护其他家庭数据。
- 全局条目创建后 ID 稳定。家庭管理员不能编辑、改名、合并或删除全局条目，避免一个家庭的操作改变其他家庭；全局目录后续治理由超级管理员负责。家庭本地条目继续按现有家庭管理员规则维护。
- 共享菜谱（无家庭归属）只能引用全局分类和全局原料；家庭私菜可引用全局和本家庭条目，不可引用其他家庭条目。复制共享菜谱到家庭时保留全局原料 ID；复制后家庭可改用自己的本地原料，且不影响来源菜谱。
- 家庭库存始终按家庭隔离，即使引用全局原料也只表示该家庭自己的库存。不同家庭不会共享余量、计划需求、采购完成或库存记录。
- 同名不代表同一条目。全局原料创建时检查全局重名；本地原料可与全局同名作为家庭覆盖项，但选择时并列显示作用域，不能自动合并或覆盖全局条目。家庭内的本地重名仍拒绝。
- 现有家庭原料和自定义子分类全部保留为家庭本地记录，不自动公开或提升为全局条目。内置根分类 ID 保持稳定；旧家庭分类和原料 ID 保持稳定，避免破坏菜谱、计划、库存与备份引用。
- 共享旧菜谱不得自动关联到任何家庭原料。仅在存在确定的全局名称/别名精确匹配时才可补全全局 ID，否则保留原材料文字待人工关联。

## 设计决策

### 菜谱材料编辑

- 菜品通用材料和每个做法独有材料使用相同的选择控件，避免只关联通用材料而遗漏做法材料。
- 每行依次提供分类/子分类、该分类下可用的全局与家庭原料、烹饪用量和删除操作。
- 分类选择显示层级路径，例如“肉类 > 牛肉”。更换分类后清空当前原料选择，原料列表只显示所选分类及其子分类里的可用条目；共享菜谱编辑只显示全局原料。
- 原料支持按标准名和已确认别名搜索。选择原料后保存稳定的 `ingredientId`，菜谱仍保留烹饪用量文本。
- 当前分类下没有合适原料时，可以在菜谱编辑流程中新增原料；新增后立即选入当前行。家庭管理员可选择新增全局原料或本家庭原料；普通成员只能新增本家庭原料。全局子分类由家庭管理员新增并对所有家庭可见，本地子分类仍受家庭管理员权限保护。
- 菜品材料行不再提供逐行库存/采购覆盖选项。页面不展示“自动判断”“常备调料”“需要采购”第三栏。
- 用量仍作为做菜说明保留；计划是否计算数量由原料有效追踪方式决定。`presence` 材料不把菜谱用量带入采购数量，`quantity` 材料按原有单位与本周累计需求规则处理。

### 计划与库存判定

- 菜谱材料、计划材料和库存都以同一 `ingredientId` 聚合；名称别名仅用于兼容与搜索，不将不同原料合并。
- 原料字典中的分类用于菜单、计划和库存的一致分组。分类本身只表达归类；库存管理方式读取原料的 `defaultTrackingMode`，若已有库存记录显式覆盖，则沿用现有库存优先规则。
- `presence` 只判断家中有/没有，使用计划中的调料确认状态；不解析菜谱用量，不要求单位，不进行数量扣减。
- `quantity` 按计划中所有未完成菜品的用量汇总，再与当前家庭库存、单位和最低保有量比较；现有完成菜品扣库存和防重复规则保持不变。
- 不因“牛里脊”和“牛排”属于同一分类而合并原料或库存；只有同一原料 ID 或明确别名映射才会汇总。

### 旧菜谱兼容

- 已有 `ingredientId` 的材料保留原关联。
- 无 `ingredientId` 的材料按当前家庭原料的标准名或明确别名匹配；可靠匹配后在下次保存时补入 ID。
- 无法可靠匹配的旧材料保留原名称和用量，不丢弃、不猜测合并；编辑时显示待关联状态，可选择已有原料或就地新增。
- 旧材料可调用 AI 整理，AI 只从当前菜谱可见的原料字典中提出候选匹配：共享菜谱只可选全局原料，家庭菜谱可选全局及当前家庭原料。必须返回候选原料的真实 `ingredientId`；不允许 AI 创建原料、类别、别名、用量或菜谱内容。
- AI 每行只能返回待匹配行 ID 和候选原料 ID，或明确返回无匹配；不接收或展示 AI 自由文本理由、置信度、名称或分类。界面仅从本地字典展示原材料与候选原料的名称和分类，由用户逐项确认后才写入 `ingredientId`。
- AI 返回无匹配、无效/越权 ID、重复或遗漏行 ID、输入材料已变化时，该行保持未匹配并保留原文；不自动选择“最相似项”、不创建候选、不虚构内容。
- AI 请求只接收待匹配材料的原始名称、所属行标识和当前菜谱可见原料的 ID/作用域/标准名/已确认别名/分类路径；不接收库存数量、成员资料或无关菜谱字段。页面只接受本次请求候选集中的 ID，并在展示与应用前再次校验当前菜谱作用域及原材料行状态。
- 旧 `purchaseType` 字段不再影响追踪方式、计划分组或采购数量。旧值在读取时忽略，并在菜谱下一次保存时不再写出。计划中的手动调料确认、库存数量和采购状态不因移除该字段而清空。
- 共享菜单来源菜谱不能保存某个家庭专属原料 ID。通过“收进我家”生成家庭副本时，全局原料 ID 保持不变；未关联材料只按全局字典精确名称/别名匹配，未匹配时保留原文并在家庭菜谱编辑时提示关联。家庭副本也可改选本地条目，来源共享菜谱不被修改。

### AI 边界

- AI 仅用于辅助匹配当前菜谱可见的已有原料，不负责生成或补全菜谱、材料、用量、类别、别名、库存方式或采购状态。
- AI 不得把同类材料视为同一原料，例如不能因都属于“牛肉”而将“牛里脊”匹配成“牛排”；候选必须是同一原料或明确同义名。
- AI 结果是建议而非事实。仅确认后的有效映射可以保存；模型超时、格式错误、候选越权或无法确定时，保留旧数据并允许人工处理。
- AI 匹配不可用时，按标准名和已确认别名自动精确匹配仍可正常工作；新增原料由用户手动录入。

## 错误与边界

- 加载原料字典失败时保留菜谱草稿，不将材料静默清空；显示错误并允许重试。
- 分类被删除或原料失效时保留原材料文字与用量，标记为待修复，禁止自动替换为列表第一项。
- 保存时服务端校验作用域：共享菜谱仅能写全局原料；家庭菜谱可写全局及当前家庭原料，不能将其他家庭本地原料 ID 写入当前菜谱。
- 两个不同原料同名或别名冲突时要求用户选择，不自动改名、合并库存或覆盖身份。
- 未选择家庭时沿用现有无家庭只读/公共菜单行为，不写入家庭字典；要维护家庭原料需先进入已加入的家庭。

## 验收标准

- 菜谱通用材料和做法独有材料均可选择分类/子分类及该分类下原料，并可填写做菜用量。
- 菜谱材料行不再出现逐行采购类型选择器。
- 全局原料和全局子分类由家庭管理员新增后对所有家庭可见；家庭本地原料和分类对其他家庭不可见。
- 在菜谱编辑器新增的原料可立即被可访问范围内的家庭库存与计划选择，标准名、分类和 ID 一致。
- 可从当前分类就地添加原料；分类层级路径正确。全局与本地子分类新增均受家庭管理员权限保护，普通成员创建全局目录被拒绝。
- `presence` 原料无论菜谱用量写“适量”“2 克”或其他文本，计划均只显示有/无确认，不形成数量缺口。
- `quantity` 原料继续按周累计需求、当前库存和单位规则计算；重复菜的需求正常累加。
- 旧菜谱材料可按 ID/别名关联；不确定项保留原文并可手动修复。
- AI 只推荐当前菜谱可见字典中的真实原料 ID；确认前不修改菜谱，未匹配项不编造、不丢弃，也不阻塞手动维护。
- 旧 `purchaseType` 不再改变计划追踪模式；手动确认状态、库存和已完成菜品扣减记录不被清除。
- 家庭菜谱可关联全局及本家庭原料，共享菜谱只关联全局原料；共享来源菜谱和其他家庭的本地原料记录不受影响。
- 服务端拒绝跨家庭本地原料 ID 写入及共享菜谱关联本地原料；相关自测覆盖普通材料、presence 调料、旧数据与共享菜谱复制路径。

## 实施范围

覆盖菜谱编辑器中的全局/家庭原料选择、新增入口、全局/家庭子分类、旧菜谱兼容、菜谱保存和计划/库存关联验证。保持现有账户、家庭角色、AI 配置、采购确认、库存扣减和共享菜单权限规则。实现按测试先行，完成后运行主自测、便携包自测并更新用户指定的便携版输出。
