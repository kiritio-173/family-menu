# 菜谱原料统一选择设计

日期：2026-10-21

## 目标

让家庭菜谱中的材料、周计划和家庭库存使用同一家庭原料字典。录入菜谱材料时先选分类/子分类，再选该分类下的原料并填写烹饪用量；原料不存在时可在当前分类中就地新增。菜谱材料不再单独选择“自动判断 / 常备调料 / 需要采购”，计划和库存按原料字典及库存记录确定管理方式。

## 设计决策

### 菜谱材料编辑

- 菜品通用材料和每个做法独有材料使用相同的选择控件，避免只关联通用材料而遗漏做法材料。
- 每行依次提供分类/子分类、该分类下的家庭原料、烹饪用量和删除操作。
- 分类选择显示层级路径，例如“肉类 > 牛肉”。更换分类后清空当前原料选择，原料列表只显示所选分类及其子分类里的原料。
- 原料支持按标准名和已确认别名搜索。选择原料后保存稳定的 `ingredientId`，菜谱仍保留烹饪用量文本。
- 当前分类下没有合适原料时，可以在菜谱编辑流程中新增原料；新增后立即选入当前行。新增分类沿用现有家庭管理员权限，不从普通成员路径绕过分类维护权限。
- 菜品材料行不再提供逐行库存/采购覆盖选项。页面不展示“自动判断”“常备调料”“需要采购”第三栏。
- 用量仍作为做菜说明保留；计划是否计算数量由原料有效追踪方式决定。`presence` 材料不把菜谱用量带入采购数量，`quantity` 材料按原有单位与本周累计需求规则处理。

### 计划与库存判定

- 菜谱材料、计划材料和库存都以同一 `ingredientId` 聚合；名称别名仅用于兼容与搜索，不将不同原料合并。
- 原料字典中的分类用于菜单、计划和库存的一致分组。分类本身只表达归类；库存管理方式读取原料的 `defaultTrackingMode`，若已有库存记录显式覆盖，则沿用现有库存优先规则。
- `presence` 只判断家中有/没有，使用计划中的调料确认状态；不解析菜谱用量，不要求单位，不进行数量扣减。
- `quantity` 按计划中所有未完成菜品的用量汇总，再与当前家庭库存、单位和最低保有量比较；现有完成菜品扣库存和防重复规则保持不变。
- 不因“牛里脊”和“牛排”属于同一分类而合并原料或库存；只有同一原料 ID 或明确别名映射才会汇总。

### 旧菜谱兼容

- 已有 `ingredientId` 的材料保留原关联。
- 无 `ingredientId` 的材料按当前家庭原料的标准名或明确别名匹配；可靠匹配后在下次保存时补入 ID。
- 无法可靠匹配的旧材料保留原名称和用量，不丢弃、不猜测合并；编辑时显示待关联状态，可选择已有原料或就地新增。
- 旧 `purchaseType` 字段不再影响追踪方式、计划分组或采购数量。旧值在读取时忽略，并在菜谱下一次保存时不再写出。计划中的手动调料确认、库存数量和采购状态不因移除该字段而清空。
- 共享菜单来源菜谱不能保存某个家庭专属原料 ID。通过“收进我家”生成家庭副本时，按当前家庭字典匹配材料；未匹配的材料保留并在家庭菜谱编辑时提示关联。来源共享菜谱不被修改。

## 错误与边界

- 加载原料字典失败时保留菜谱草稿，不将材料静默清空；显示错误并允许重试。
- 分类被删除或原料失效时保留原材料文字与用量，标记为待修复，禁止自动替换为列表第一项。
- 保存时服务端继续校验家庭原料与家庭菜谱归属一致，不能将其他家庭的原料 ID 写入当前家庭菜谱。
- 两个不同原料同名或别名冲突时要求用户选择，不自动改名、合并库存或覆盖身份。
- 未选择家庭时沿用现有无家庭只读/公共菜单行为，不写入家庭字典；要维护家庭原料需先进入已加入的家庭。

## 验收标准

- 菜谱通用材料和做法独有材料均可选择分类/子分类及该分类下原料，并可填写做菜用量。
- 菜谱材料行不再出现逐行采购类型选择器。
- 在菜谱编辑器新增的原料可立即被该家庭库存与计划选择，标准名、分类和 ID 一致。
- 可从当前分类就地添加原料；分类层级路径正确，分类新增仍受家庭管理员权限保护。
- `presence` 原料无论菜谱用量写“适量”“2 克”或其他文本，计划均只显示有/无确认，不形成数量缺口。
- `quantity` 原料继续按周累计需求、当前库存和单位规则计算；重复菜的需求正常累加。
- 旧菜谱材料可按 ID/别名关联；不确定项保留原文并可手动修复。
- 旧 `purchaseType` 不再改变计划追踪模式；手动确认状态、库存和已完成菜品扣减记录不被清除。
- 家庭副本可关联当前家庭字典；共享来源菜谱和其他家庭的原料记录不受影响。
- 服务端拒绝跨家庭原料 ID 写入；相关自测覆盖普通材料、presence 调料、旧数据与共享菜谱复制路径。

## 实施范围

覆盖菜谱编辑器中的家庭原料选择、新增入口、旧菜谱兼容、菜谱保存和计划/库存关联验证。保持现有账户、家庭角色、AI 配置、采购确认、库存扣减和共享菜单权限规则。实现按测试先行，完成后运行主自测、便携包自测并更新用户指定的便携版输出。
