# 全局用户身份与多家庭使用流程设计

**日期：** 2026-10-16  
**状态：** 已确认，等待拆分实施计划  
**适用范围：** 新设备登录/注册、跨家庭身份、家庭创建与加入、导航和权限体验

## 1. 背景与目标

当前版本把登录身份保存在家庭成员对象里。一个人换到另一个家庭时，需要重新认领成员，登录 ID 和密码也可能在不同家庭重复，用户很难理解“我是谁”和“我能管理什么”的关系。

本次改版把身份提升为平台级用户账户，家庭只保存成员关系和角色。用户在新设备上先登录或注册，之后始终使用同一个身份，可以申请加入多个家庭，也可以直接创建家庭。一个用户最多加入 5 个有效家庭；创建家庭后立即成为该家庭管理员，不需要超级管理员批准。

产品目标：

- 新设备首次使用有明确的登录/注册入口，不先展示半匿名的家庭数据。
- 用户身份跨家庭保持一致，切换家庭只是切换当前工作范围。
- 家庭创建、申请加入、管理员授权和普通成员权限有清晰边界。
- 菜单成为第一入口，账户、家庭和配置集中在最后的设置入口。
- 现有菜谱、作者、家庭和历史记录可以平滑迁移。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 全局身份 | 采用“全局用户账户 + 家庭成员关系”模型 |
| 默认登录 ID | 首次打开时自动生成一个全局唯一、可修改的 ID，例如 `用户-AB12` |
| 初始密码 | 新账户初始密码为 `123456`，允许继续使用，但界面持续提示风险 |
| 家庭上限 | 一个用户已加入的有效家庭总数最多 5 个；待处理申请不占名额 |
| 创建家庭 | 不需要超级管理员批准；创建者立即成为家庭管理员 |
| 家庭管理员 | 一个家庭可以有多个管理员；不能删除或降级最后一名管理员 |
| 平台配置权限 | 继续使用全局管理口令 `adminPin` 解锁，不新增平台管理员账号；只负责服务器设置、备份、AI 和数据维护，不审批普通家庭创建 |
| 主导航 | 菜单第一栏，设置最后一栏 |
| 私菜入口 | 私菜不单独占底部栏目，在菜单页用“全部 / 共享 / 我家私房”筛选 |

## 3. 用户生命周期

### 3.1 新设备首次进入

1. 应用打开后先显示登录/注册页。
2. 未登录用户不能进入家庭菜单数据。
3. 注册时自动生成登录 ID，用户可以立即修改；登录 ID 在全平台唯一，支持汉字、字母、数字和常用符号。
4. 初始密码为 `123456`。用户可以继续使用，但页面显示风险提示，不强制修改。
5. 登录成功后，本机保存用户会话令牌和上次选择的家庭；密码不保存到浏览器。

### 3.2 登录后的家庭选择

登录后进入“我的家庭”页：

- 已加入的家庭显示家庭名称、当前角色、成员数和待处理事项。
- 点击家庭进入该家庭的菜单首页。
- 没有家庭时显示“创建家庭”和“申请加入其他家庭”。
- 已加入 5 个家庭后，创建家庭和批准新加入的操作都返回明确提示，要求先退出一个家庭。
- 当前家庭选择保存在本机，不改变用户在其他设备上的默认家庭。

### 3.3 创建家庭

用户填写家庭名称、图标和备注后即可创建。服务端检查用户当前有效家庭数小于 5，创建成功后：

- 新家庭状态立即可用，不进入平台审批队列。
- 创建者自动建立 `owner` 成员关系。
- 创建者可以继续邀请或批准其他成员。
- 家庭菜单中的共享菜、做饭状态和成员管理立即按管理员权限开放。

### 3.4 申请加入家庭

用户从家庭入口提交申请，申请包含目标家庭、显示名和可选留言。目标家庭管理员批准后建立 `member` 关系；拒绝时保留申请结果，申请人可以看到结果。批准前不增加家庭数量，也不能读取目标家庭的私菜、点餐或库存。

## 4. 身份与数据模型

### 4.1 全局用户

建议新增 `users.json`，每条记录包含：

```text
id              不可变的内部 userId
loginId         全平台唯一的用户可见登录 ID
passwordHash    新账户使用摘要存储（与全局 adminPin 分开）
displayName     默认显示名，可单独修改
emoji           用户头像
createdAt
updatedAt
```

新设备令牌绑定 `userId`，不再绑定单个家庭。切换家庭时，服务端根据 `userId + householdId` 重新检查成员关系和角色。

### 4.2 家庭成员关系

家庭保存成员关系或引用独立的 `household_members` 数据：

```text
householdId
userId
role           owner / member
joinedAt
updatedAt
```

家庭资料继续保存名称、图标、备注和创建者。家庭管理员是关系上的 `owner`，不是全局用户类型；同一用户在不同家庭可以分别是管理员或普通成员。

### 4.3 密码和令牌

- 新账户密码用摘要保存；服务端接口不返回密码明文。
- `123456` 是产品确定的初始值，登录页显示“建议修改密码”的风险提示。
- 用户账户密码和全局 `adminPin` 是两套凭证。用户密码用于登录个人身份；`adminPin` 用于解锁平台级设置。
- 本地部署没有短信或邮箱找回；用户忘记账户密码时，通过本地数据恢复或兼容的管理员维护流程处理。
- 令牌只代表用户身份，不自动代表某个家庭管理员权限；每个写操作仍检查当前家庭和对象归属。

## 5. 权限模型

| 能力 | 普通成员 | 家庭管理员 | 全局管理口令解锁 |
| --- | --- | --- | --- |
| 查看当前家庭共享菜单 | ✓ | ✓ | ✓ |
| 点餐、库存、计划、留言 | ✓ | ✓ | ✓ |
| 新增/修改/删除自己的私菜 | ✓ | ✓ | ✓ |
| 修改共享菜单和共享分类 | — | 本家庭范围 | 全局 |
| 修改别人的本家私菜 | — | 本家庭范围 | 全局 |
| 更新做饭状态、删除/清空点餐 | — | 本家庭范围 | 全局 |
| 管理本家庭成员和加入申请 | — | 本家庭范围 | 全局 |
| 新增或撤销家庭管理员 | — | 本家庭范围，不能撤销最后一人 | 全局 |
| 创建家庭 | ✓，受 5 户上限约束 | ✓，受 5 户上限约束 | ✓ |
| 全局设置、备份、AI、数据维护 | — | — | ✓ |

服务端是最终权限裁判。前端根据当前用户和家庭角色隐藏不可用入口，但任何请求即使绕过前端也必须由服务端拒绝。

## 6. 页面与导航

底部固定六栏：

1. **菜单**：第一栏，进入后直接展示当前家庭菜单。
2. **计划**：本周/下周安排。
3. **点餐**：点餐单、买菜汇总和做饭状态。
4. **留言**：家庭留言和菜品互动。
5. **库存**：当前家庭库存。
6. **设置**：最后一栏，集中放身份、家庭和配置。

菜单页内部提供：

- `全部`：共享菜单和本家庭私菜。
- `共享`：所有家庭可见的共享菜。
- `我家私房`：当前家庭的全部私菜。
- 普通成员只能操作自己添加的私菜；管理员可以操作本家庭共享菜和全部本家私菜。

设置页按权限显示卡片：

- 所有人：我的账户、登录 ID、密码风险提示、退出登录、切换家庭。
- 普通成员：申请加入家庭、当前家庭信息、我的私菜入口。
- 家庭管理员：创建家庭、成员管理、加入申请、管理员角色、家庭资料、共享菜单和做饭状态。
- 输入全局管理口令后：全局设置、备份恢复、AI 配置、数据维护。

## 7. 旧数据迁移

迁移按旧成员的稳定内部 ID 处理，不按显示名自动合并：

1. 每个旧成员生成一个全局用户账户，并保留原家庭成员关系。
2. 旧登录 ID 在全平台冲突时自动追加短后缀，用户登录后可以修改。
3. 旧家庭成员的角色沿用；现有管理员继续是管理员。
4. 菜品作者、留言作者和历史记录改为引用 `userId`，不丢失作者信息。
5. 旧设备令牌统一失效一次，用户重新登录；新令牌改为用户级令牌。
6. 没有个人密码的旧成员进入登录/认领兼容流程，完成后生成全局账户密码。
7. 旧的家庭口令仅作为兼容管理凭证保留，不能替代用户登录，也不能跨家庭使用。

迁移过程必须可重复执行：重复启动不会创建重复用户、重复成员关系或重复家庭。

## 8. 异常与恢复

- 登录 ID 已存在：提示用户修改，不能静默覆盖已有用户。
- 加入第六个家庭：拒绝并提示先退出一个已加入家庭。
- 最后一名管理员尝试退出、删除或降级：拒绝，要求先转移管理员或删除家庭。
- 普通成员访问管理员入口：前端隐藏，接口返回明确的权限提示。
- 目标家庭不存在或已删除：申请失败，不产生悬空关系。
- 忘记账户密码：通过本地数据恢复或兼容的管理员维护流程处理；不设计云端找回流程。全局管理口令仍按当前版本的 `data/settings.json` 维护规则处理。
- 旧设备没有有效令牌：回到登录页，不显示半匿名的家庭工作区。

## 9. 分阶段实施

### 阶段一：账户和关系层

- 新增用户账户存储、全局登录 ID、密码摘要和用户令牌；保留全局 `adminPin` 作为平台配置解锁凭证。
- 增加家庭成员关系引用和 5 户上限。
- 完成旧数据迁移与兼容接口。

### 阶段二：登录与家庭工作区

- 新设备登录/注册门禁。
- 登录后家庭选择、创建家庭、申请加入和家庭切换。
- 角色状态统一从用户关系计算。

### 阶段三：导航与菜单体验

- 菜单固定第一栏，设置固定最后一栏。
- 菜单内共享/私菜筛选。
- 设置页按角色显示功能卡片。

### 阶段四：验证与发布

- 扩展服务端权限自测和迁移自测。
- 运行语法检查、完整自测、便携版冷启动和发布自检。
- 重新生成 `package/家庭菜单-便携版/` 与 ZIP。
- 只提交源代码、测试和文档，不提交真实数据、备份、令牌或临时可视化文件。

## 10. 验收标准

- 新设备打开后必须先登录或注册。
- 注册自动生成可修改登录 ID，初始密码为 `123456`，页面显示风险提示。
- 同一用户可以加入最多 5 个有效家庭，并在家庭间切换而不重新认领身份。
- 创建家庭不需要平台管理员批准，创建者立即成为管理员。
- 全局设置、备份、AI 和数据维护继续要求输入全局管理口令，不把家庭管理员自动提升为平台配置管理员。
- 一个家庭可以有多个管理员，最后一名管理员不能被删除或降级。
- 普通成员只能维护自己的私菜，不能修改共享菜单、别人私菜或做饭状态。
- 菜单位于第一栏，设置位于最后一栏，角色不同看到的设置功能不同。
- 旧数据迁移后家庭、成员、作者、菜单和历史记录保持对应关系。
- 服务端权限测试、迁移测试、前端语法检查和便携版发布检查全部通过。
