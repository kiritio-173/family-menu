# 家庭库存余量与采购识别设计

日期：2026-10-19

## 目标

让当前家庭的采购清单能够根据库存余量判断“已有、库存不足、待购买”，并允许家庭成员自行维护库存数量和单位。库存属于家庭工作区，继续沿用现有全局账户与多家庭权限模型。

## 规则

1. 库存条目保存 `quantity`、`unit`、`name`，数量允许用户直接输入或用加减按钮调整，最小为 0。
2. 采购需求从当前采购范围内的菜谱调料汇总，同名调料合并；能解析数量的需求保留总量和需求单位。
3. 采购条目状态按以下顺序计算：
   - 当前家庭没有同名库存，或库存合计为 0：`待购买`；
   - 库存单位与需求单位相同，且需求数量可解析：库存合计大于等于需求量为 `已有`，否则为 `库存不足`，并显示缺口；
   - 菜谱用量为“适量、少许、若干”等无法解析的文字，或库存和需求单位不一致：有库存时显示“已有，需确认余量”，没有库存时显示“待购买”。
4. 多个同名库存条目只在单位一致时合计；单位不同则并列展示，不进行错误换算。
5. 采购状态“已完成”表示成员已经买到但尚未入库；库存有余量时优先显示库存判断结果。入库后清除该调料的“已完成”状态。
6. 普通成员、家庭管理员和超级管理员都可以维护当前家庭库存和采购状态；库存写入仍由服务端按当前家庭成员关系校验。
7. 库存不足只提示补购，不自动扣减库存，也不改变库存余量；用户可在库存页或采购页手动调整。

## 数据流

```text
菜谱调料用量
    │ 汇总同名调料、解析数量和单位
    ▼
当前家庭采购清单
    │ 读取当前家庭库存
    ├─ 无库存/余量为 0 ─────────► 待购买
    ├─ 同单位且余量 ≥ 需求 ──────► 已有
    ├─ 同单位且余量 < 需求 ──────► 库存不足（显示缺口）
    └─ 单位不同或无法解析 ───────► 有库存但需确认余量

已完成 ──入库──► 库存数量增加，并清除已完成状态
```

## 服务端改动

- 扩展采购清单所需的标准化数据辅助函数，保持 `pantry.json` 的兼容格式。
- 不改变库存接口路径和权限，只确保数量仍按 0 到 99999、最多三位小数保存。
- 采购状态接口继续保存 `needed` / `completed`，库存判断由读取端实时计算。

## 前端改动

- 采购条目增加需求量、库存余量、状态标签和缺口提示。
- “已有”继续显示库存明细；“库存不足”显示“还需 X 单位”，并保留入库/调整入口。
- 无法比较时显示“请确认余量”，不把不同单位强行换算。
- 库存编辑表单继续允许自由输入数量和单位；保存后立即刷新采购状态。

## 验收

- 同单位且库存足够显示“已有”。
- 同单位但库存不足显示“库存不足”和正确差额。
- 无库存或数量为 0 显示“待购买”。
- “适量”或单位不一致时显示“需确认余量”，不报错误差额。
- 多个同名同单位库存正确合计；不同单位不合计。
- 普通成员可以调整库存、标记采购已完成和入库，不出现管理口令提示。
- 切换家庭后采购和库存判断只使用目标家庭数据。
- 旧的库存数据、便携版构建和现有自测全部通过。
