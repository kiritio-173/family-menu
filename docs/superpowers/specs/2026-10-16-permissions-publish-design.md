# 家庭菜单权限与发布流程设计

## 目标

普通用户可以完成家庭日常操作，也可以维护当前家庭的私有菜谱和分类；共享菜单、家庭管理、系统设置、备份和 AI 等管理能力由管理员口令保护。每次发布都应先验证，再生成便携版，并提交推送到 GitHub。

## 权限边界

服务端继续以管理口令会话作为管理员身份。`/api/dishes`、`/api/categories`、`/api/households`、`/api/settings`、备份、上传和 AI 写操作需要管理员会话；`/api/my-dishes` 与 `/api/my-categories` 不需要管理员会话，但请求必须带有效家庭 ID，且更新/删除只能命中该家庭自己的私有资源。点餐、库存、计划、留言、互动和加入申请保持普通用户可用，加入申请的批准与拒绝需要管理员。

未设置管理口令时，系统保持兼容旧版本的开放模式：所有访问者按管理员处理。要区分管理员和普通用户，管理员需要先设置管理口令。

## 发布流程

`publish-update.js` 是唯一的发布入口。它检查版本号、运行语法检查和 `_selftest.js`，调用 `build-package.js` 生成 `package/家庭菜单-便携版/` 与 ZIP，随后只暂存明确的应用文件，提交当前分支并推送到 `origin`。数据、上传照片、备份、打包产物和临时脚本不会进入 Git 提交。

## 验证

权限回归用例覆盖普通用户新增私有分类/菜谱、修改共享菜谱和修改系统设置。发布自检验证发布文件清单不包含本地数据或打包目录。便携版使用 `_packtest.js` 做解压和冷启动检查。
